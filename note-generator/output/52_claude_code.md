# 非エンジニアがClaude Codeで詰まる場所ベスト5と解決策

---

## 最初に正直に言います

Claude Codeを使い始めた最初の1週間、私は3回諦めかけました。

「ターミナルが怖い」「エラーの意味がわからない」「何を指示すればいいのかすらわからない」。

エンジニアじゃない人間がAIコーディングツールを使うとき、躓くポイントは大体同じです。この記事は、そのつまずき5箇所と、私が実際に試した解決策をまとめたものです。

---

## 私のスペック（参考までに）

沖縄在住の会社員、佐伯亮です。

プログラミングは「なんとなく読める」程度。フロントエンドをちょっと触ったことはあるけど、バックエンドはほぼ素人。GitHubのコマンドは都度ググっていました。

そんな状態で、Claude Codeを使ってWebアプリを2本リリースしました。時間はかかりました。でも、できた。

その過程で「あ、これは非エンジニアあるある詰まりポイントだな」と感じた場所が5箇所あります。

---

## そもそもClaude Codeとは何か（30秒で）

Claude CodeはAnthropicが作ったCLIツールです。ターミナルから起動して、AIと会話しながらコードを書いたり、ファイルを編集したり、コマンドを実行したりできます。

ChatGPTと何が違うかというと、**ファイルに直接触れる**点です。

ChatGPTにコードを書いてもらっても、自分でコピペして、ファイルを作って、保存して……という手間がある。Claude Codeは「このファイルを編集して」「このコマンドを実行して」が直接できます。

それが強みでもあり、非エンジニアが怖いと感じる理由でもあります。

---

## 詰まる場所ベスト5【無料パート】

### 第5位：インストールで止まる

これ、意外と多いです。

Claude Codeを使うにはNode.jsが必要で、npmでインストールします。「npm install -g @anthropic-ai/claude-code」というコマンドを打てばいい。

でも私が最初に詰まったのは、**Node.jsのバージョン**でした。

古いNode.jsが入っていると、インストール時にエラーが出ます。エラー文の中に「requires Node 18 or higher」みたいな記述があっても、そもそも意味がわかりません。

**解決策：** インストール前に「node -v」を打って、バージョンを確認する。18未満なら、Node.jsの公式サイトから最新版をダウンロードして入れ直す。それだけです。

私の場合、これで30分溶かしました。

---

### 第4位：APIキーの設定がわからない

「ANTHROPIC_API_KEY」という環境変数を設定しないといけないのですが、この「環境変数」という概念が最初はわかりません。

「どこに書けばいいの？」「書いたのに反映されない？」「毎回打つの？」

私はMacを使っているので、`.zshrc`に書けばいい、と知るまでに時間がかかりました。Windowsの方は別の手順が必要です。

**解決策：** ターミナルで以下を1行打つだけです（Mac/Linuxの場合）。

```
export ANTHROPIC_API_KEY="sk-ant-xxxxxx"
```

ただし、これだと**ターミナルを閉じると消えます**。永続化するには`.zshrc`や`.bashrc`に同じ行を追記する必要があります。Windowsはシステムの環境変数から設定します。

この違いを知らずに「なんか毎回消える」と悩んでいる人、結構います。

---

### 第3位：何を指示すればいいかわからない

Claude Codeを起動したとき、最初に「何を作りたいですか？」と聞かれるわけではありません。ただカーソルが点滅しているだけです。

非エンジニアあるあるで、「どのくらい細かく指示すればいいのか」が最初わかりません。

「TODOアプリを作って」と言えばいいのか。「Reactを使って、LocalStorageに保存する、追加・削除・チェックができるTODOアプリを作って」と言わないといけないのか。

**解決策：** 私の経験上、最初は**曖昧でいい**です。

「シンプルなTODOアプリを作りたい。Reactで、データはブラウザに保存する」くらいで動き始めます。Claude Codeが「技術スタックはどうしますか？」「ファイル構成はこうしましょうか？」と聞き返してくれます。

最初から完璧な指示を出そうとして固まるより、雑に投げて会話しながら詰めていく方が早い。これは体感として強く感じました。

---

以上が第5位〜第3位です。

第2位と第1位は、もう少し深い話になります。エラーの読み方と、CLAUDE.mdの使い方。

この2つを押さえると、作業効率が体感で3倍くらい変わります。

有料パートでは、**実際のエラーメッセージと私がClaude Codeに送ったプロンプトをそのまま載せています**。「こういう文章で投げればいいんだ」という感覚がつかめると思います。

---ここから有料---

### 第2位：エラーが出たとき何をすればいいかわからない

これが一番時間を溶かした詰まりポイントです。

Claude Codeを使い始めると、必ずエラーに出会います。ターミナルに赤い文字が出て、処理が止まる。

非エンジニアが最初にやりがちなのが「エラー文を全部コピーしてClaude Codeに貼り付ける」です。これ、悪くはないんですが、エラーの本質的な行だけを伝えないと、AIも「ふわっとした返答」をしてくることがあります。

私が詰まった実例を出します。

あるとき、こんなエラーが出ました。

```
Error: Cannot find module './components/Header'
Require stack:
- /Users/saeki/projects/myapp/src/App.js
```

最初は「えっ何が起きてるの」と全文をそのままClaude Codeに投げていました。でもそれだと返答が長くなりすぎて、どこを直せばいいか追いきれないことがありました。

**解決策：エラーを「3点セット」で伝える**

私が今やっている方法はこれです。

1. **エラーの最初の1〜2行**（原因が書いてある部分）
2. **「どこで」起きているか**（ファイル名や行番号）
3. **「その前に何をしたか」**（直前の操作）

実際にClaude Codeに送ったプロンプトはこうです。

```
「Cannot find module './components/Header'というエラーが出ています。
App.jsの中でHeaderをimportしようとした後に出ました。
このエラーの原因と修正方法を教えてください。」
```

これだけで、「HeaderフォルダかHeaderファイルが存在しないか、パスが違う可能性があります。以下を確認してください」と的確に返ってくるようになりました。

エラー文を丸投げするより、**自分でちょっと整理して投げる**。そのほうが結果的に速い。

---

**エラーの種類別・私が使っているプロンプトテンプレ**

よく出るエラーに合わせて、私が使い回しているプロンプトを3つ公開します。

**（1）モジュールが見つからない系**
```
「〇〇というモジュールが見つからないエラーが出ています。
npmでインストールしたはずなのですが、何が問題か確認してもらえますか？
package.jsonと現在のエラー文を添付します。」
```

**（2）型エラー・undefined系（TypeScript含む）**
```
「〇〇はundefinedだというエラーです。
△△というコンポーネントで□□というデータを渡そうとしたときに出ました。
props型の定義を見直してもらえますか？」
```

**（3）CORS・APIエラー系**
```
「フロントからAPIを叩いたらCORSエラーが出ました。
フロントはlocalhost:3000、バックエンドはlocalhost:8000で動かしています。
バックエンドのCORS設定を確認してもらえますか？」
```

この3パターンで、私のWebアプリ開発中に出たエラーの約7割は解決できました。

### 第1位：CLAUDE.mdを使っていない

これが最大の詰まりポイント、というか「もったいない使い方」です。

CLAUDE.mdとは、プロジェクトのルートに置くMarkdownファイルです。ここに書いた内容を、Claude Codeはセッションをまたいで「記憶」してくれます。

非エンジニアが詰まるのは、**毎回同じ説明を繰り返す**という問題です。

「このプロジェクトはReactとSupabaseを使っています」「認証はJWTです」「スタイルはTailwindを使っています」——こういう説明を毎回セッションの最初にしていると、時間がかかるし、指示がブレます。

CLAUDE.mdに書いておけば、セッションを開始した瞬間にClaude Codeがプロジェクトの文脈を把握した状態で動いてくれます。

**私が実際に使っているCLAUDE.mdの中身**

私の最初のWebアプリ開発時に使ったCLAUDE.mdを、そのまま公開します（一部省略）。

```markdown
# プロジェクト概要
- 名前：タスク管理アプリ「Shigoto」
- フロントエンド：React (Vite)
- バックエンド：Supabase
- スタイリング：Tailwind CSS
- デプロイ先：Vercel

# ディレクトリ構成
/src
  /components  # 再利用コンポーネント
  /pages       # ページコンポーネント
  /hooks       # カスタムフック
  /lib         # Supabase client等

# コーディングルール
- コンポーネントはfunction宣言で書く（アロー関数不可）
- 型はTypeScriptで定義する
- CSSはTailwindのユーティリティクラスのみ使う
- コメントは日本語でOK

# 注意事項
- Supabaseのテーブル名はスネークケース
- 環境変数は.env.localに書く（コミット禁止）
- エラーハンドリングは必ずtry-catchで書く

# 今やっていること
認証機能の実装中。ログイン・サインアップページは完成済み。
次はダッシュボードページを作る。
```

これだけ書いておくと、毎回「このプロジェクトは〜」という前置きが不要になります。

体感で、1セッションあたり10〜15分の節約になりました。1日3セッション動かせば、1ヶ月で約15時間の差が出ます。

---

**CLAUDE.mdを書くときの3つのコツ**

コツは3つあります。

**① 「今やっていること」を毎回更新する**

CLAUDE.mdの最後に「今やっていること」という項目を作って、その日の作業前に更新します。「認証機能実装中」「フォームのバリデーション追加中」など1行でOKです。

これで「前回どこまでやったっけ？」という時間がゼロになります。

**② 「やってはいけないこと」を書く**

Claude Codeは賢いですが、プロジェクト固有のルールは教えないとわかりません。「このファイルは直接触らないで」「このAPIは廃止予定だから使わないで」という禁止事項を書いておくと、余計な修正が入りません。

**③ 最初は短くていい**

CLAUDE.mdを完璧に書こうとして時間がかかるくらいなら、3〜4行から始めて良いです。使いながら追記する方が、実態に即した内容になります。

---

## 5つのポイントまとめ

改めて整理します。

| 順位 | 詰まりポイント | 解決策 |
|------|--------------|--------|
| 5位 | インストールで止まる | `node -v`でバージョン確認から |
| 4位 | APIキーの設定がわからない | `.zshrc`に永続化して書く |
| 3位 | 何を指示すればいいかわからない | 最初は雑に投げてOK |
| 2位 | エラーへの対処がわからない | 3点セット（内容・場所・直前操作）で投げる |
| 1位 | CLAUDE.mdを使っていない | プロジェクトの文脈を最初に書いておく |

---

## 最後に

非エンジニアがClaude Codeを使うとき、「コードが書けない」ことは実はそんなに問題じゃないです。

詰まるのは、もっと手前の部分——環境設定、エラーの読み方、指示の粒度感。

でも、この5箇所さえ押さえておけば、あとは「AIに指示を出しながら進める」という作業になります。それは、エンジニアじゃなくてもできます。

私が最初に作ったWebアプリは、完成まで約3週間かかりました。でも2本目は1週間でした。慣れます。

この記事が、Claude Code入門の最初の一歩になれば嬉しいです。
