# Claude Codeを使う前に知っておきたかった基礎知識

---

## 正直に言います。最初の3日間、何もできませんでした。

Claude Codeを知って、すぐに試してみた。

ターミナルを開いて、インストールして、さあやってみようと思ったら――「で、何を入力すればいいの？」という状態になった。

同じような経験、ありませんか。

「AIがコードを書いてくれる」というのは知っていた。でも、どう使えばいいのか、どんな知識が必要なのか、そこが全然わかってなかった。この記事では、あのときの自分に教えてあげたかったことを、まとめて書きます。

---

## 自分の話を少しだけ

沖縄で会社員をしながら、副業でアプリ開発をやっています。

エンジニアではありません。プログラミングを独学で少し齧った程度で、仕事はまったく別の職種です。Kindle本を8冊出して、Webアプリを2本リリースして、最近はClaude Codeをメインの開発ツールとして使っています。

Claude Codeを使い始めたのは、リリース済みのWebアプリに機能を追加しようとしたのがきっかけでした。既存のコードがあって、それを改修するのに使いはじめた感じです。

最初はとにかく戸惑った。ChatGPTとは違う。コードを書いてくれるんじゃなくて、コードを「実行しながら」作ってくれる感覚。この違いが最初はうまく掴めなかったです。

---

## Claude Codeって何が違うの？

まず、ChatGPTやClaude.aiとClaude Codeは「別物」だと思ったほうがいいです。

ChatGPTにコードを書いてもらうのは「提案をもらう」イメージ。自分でそれをコピーして、ファイルに貼り付けて、実行してみる。そういう作業が全部自分の手でやる必要がある。

Claude Codeは違います。

ターミナル（コマンドライン）から動かすツールで、自分のパソコンのファイルに直接アクセスして、コードを書いて、テストして、エラーが出たら直して、という一連の作業を自律的にやってくれる。

「エージェント型」という言葉をよく見ますが、要するに「指示を受けてから自分で判断して動く」という動き方です。

具体的にやってくれること：

- ファイルを読んで内容を把握する
- コードを書いてファイルに保存する
- ターミナルでコマンドを実行する
- エラーを見てデバッグする

これを人間が何も操作しなくても、連続でやってくれます。ここが一番大きな違いです。

---

## 使う前に知っておくべき3つのこと

### 1. ターミナルの基本は避けて通れない

Claude Codeはターミナル（Macなら「ターミナル.app」、Windowsなら「コマンドプロンプト」や「PowerShell」）から動かします。

GUIのアプリではないので、最初は戸惑います。

最低限これだけ知っていれば動かせる、というコマンドがあります：

- `cd フォルダ名`：フォルダに移動する
- `ls`（Macの場合）：今いるフォルダのファイル一覧を見る
- `claude`：Claude Codeを起動する

これだけです。本当にこれだけ知っていれば、とりあえず起動はできます。

でも「とりあえず起動できる」と「使いこなせる」は全然別の話で、それが有料パートで書きたいことです。

### 2. プロジェクトの構造を理解していないと指示が通らない

これが最初の大きなつまずきでした。

Claude Codeに「ログイン機能を作って」と伝えたとき、どこのファイルに何を書けばいいか、Claudeは推測してくれます。でも、プロジェクトの構造が複雑だったり、独自のルールがあったりすると、ズレた場所にコードを書かれることがある。

たとえば、Reactを使っているのか、Next.jsを使っているのか、Supabaseで認証しているのか。これを最初に正確に伝えないと、Claudeは「一般的な方法」でコードを書いてしまう。

「CLAUDE.md」というファイルを使う方法があります。プロジェクトのルートフォルダにこのファイルを置いておくと、Claude Codeが起動したときに自動で読み込んでくれます。いわば、AIへの「引き継ぎ書」みたいなものです。

これを使うかどうかで、作業の精度がかなり変わります。

### 3. 「一度に全部お願いする」のは失敗のもと

最初にやってしまった失敗です。

「ToDoアプリを作って。ログインできて、タスクを追加・削除できて、期限も設定できて、リマインドも送れて、スマホでも使えるようにして」

全部一気にお願いした。

結果、Claudeはコードを書いてくれたけど、エラーが次々に出て、それを直そうとするとまた別のエラーが出て、最終的にぐちゃぐちゃになった。

正解は、小さく分けること。

「まずToDoアプリの画面だけ作って。データの保存はまだいい」「次にSupabaseに接続する部分だけ作って」という順番でやると、格段にうまくいきます。

これはClaude Codeに限らず、AIとの作業全般に言えることですが、Claude Codeは「自律的に動く」分、指示が大きいほど暴走しやすい。

## CLAUDE.mdの書き方と実際に使っているテンプレート

CLAUDE.mdは、Claude Codeへの「前提情報」を書いておくファイルです。

プロジェクトのルートフォルダ（一番上の階層）に置くと、Claude Codeが起動したときに自動で読み込んでくれます。

これがあるとないとでは、作業の精度が全然違います。

自分が実際に使っているテンプレートを公開します。

```
# プロジェクト概要
このプロジェクトは〇〇のためのWebアプリです。

# 技術スタック
- フロントエンド：Next.js 14（App Router）
- バックエンド：Supabase（認証・DB）
- スタイリング：Tailwind CSS
- デプロイ：Vercel

# フォルダ構成
- /app：ページコンポーネント
- /components：共通UIコンポーネント
- /lib：Supabaseクライアントなど

# コーディングルール
- TypeScriptを使う
- コンポーネントはすべて /components に置く
- 環境変数は .env.local に入れる（絶対にコードに直書きしない）

# よくやる作業
- UIの変更：shadcn/uiのコンポーネントを使うこと
- DB操作：Supabaseのクライアントは /lib/supabase.ts を使うこと
```

ポイントは「技術スタック」と「フォルダ構成」と「ルール」の3つを書いておくことです。

特に「フォルダ構成」が重要でした。

これがないと、Claudeはファイルをどこに置けばいいか毎回推測することになる。そのせいで、意図しない場所にファイルを作られたことが何度もありました。

CLAUDE.mdを書いてからは、そういうズレがほとんどなくなりました。

## 指示の出し方：実際に使っているパターン

Claude Codeへの指示の出し方には、コツがあります。

### パターン①：「現状 → やってほしいこと → 制約」の順で書く

悪い例：
```
検索機能を実装してください
```

良い例：
```
現在、/app/tasks/page.tsx にタスク一覧を表示しています。
タスク名でリアルタイム検索できる検索バーを追加してください。
Supabaseのクエリは既存の getTasks 関数を参考にしてください。
新しいコンポーネントは /components/SearchBar.tsx に作ってください。
```

この「現状 → やってほしいこと → 制約」の形を意識するだけで、精度が上がります。

「制約」の部分が特に重要で、「既存のどのファイルを参考にするか」「どこに新しいファイルを作るか」を明示すると、ズレが減ります。

### パターン②：エラーが出たときはエラー文をそのまま貼る

「エラーが出ました。直してください」ではなく、エラーメッセージ全文をそのまま貼る。

これだけで解決率が上がります。

自分の言葉で説明しようとして、かえって情報が少なくなるより、エラー文をそのまま渡したほうがClaude Codeは的確に対処してくれます。

### パターン③：作業前に「確認だけして」と言う

大きな変更をお願いするとき、いきなりコードを書いてもらわず、「どういう変更をするか教えて。コードはまだ書かないで」と最初に言うようにしました。

Claudeが提案する変更内容を先に確認して、方向性が合っていたら「じゃあ実装して」という流れにする。

これをやるようにしてから、「意図しない大きな変更をされた」というミスがなくなりました。

## 実際につまずいたポイントと解決策

### つまずき①：「Permission denied」エラーが出て動かない

使い始めのころ、何をしても「Permission denied」というエラーが出て先に進めない状態になりました。

原因はファイルの権限設定でした。

Macの場合、フォルダに対してClaude Codeが書き込めない権限になっていることがある。

解決策はターミナルで `chmod -R 755 フォルダ名` を実行することでした。これでClaude Codeがファイルを操作できるようになります。

### つまずき②：コードを書いてくれるけど動かない

コードは生成されるけど、実行すると動かない。という状態が最初は頻繁にありました。

一番の原因は「バージョンの不一致」でした。

Next.jsのバージョンが13なのにApp Routerの書き方で書かれる、Supabaseのバージョンが古いのに新しいAPIを使われる、という感じ。

CLAUDE.mdに「Next.js 14、Supabase v2.x を使っています」とバージョンまで明記するようにしてから、改善しました。

### つまずき③：気づいたら大量のファイルが作られていた

「画面を3つ作って」と言ったら、50個くらいのファイルが作られていた。

不要なものが大量に混じっていて、何が何かわからなくなりました。

解決策は作業をこまかく分けること。「まず1つ目の画面だけ作って」「OKだったら2つ目」という順番で進めると、こういう事態が起きにくくなります。

### つまずき④：変更が多すぎてGitに何を記録すればいいかわからない

Claude Codeが一度に大量のファイルを変更したとき、Gitで何をコミットすればいいかわからなくなる。

これは最初から作業単位を小さくするしかない、という結論になりました。

「1機能 = 1依頼 = 1コミット」くらいの粒度で進めると、あとで追いかけやすくなります。Gitをまだ使っていない人は、Claude Codeを使い始めるタイミングで一緒に覚えることをおすすめします。

### つまずき⑤：途中でClaude Codeが止まる

長い処理をやっていると、途中でClaude Codeが止まることがあります。

ネットワークのタイムアウトや、APIのレート制限が原因のことが多い。

止まったときは、「さっきの続きをやって」だけ言えば、だいたい文脈を引き継いで再開してくれます。ゼロから説明しなくていい場合がほとんどです。

## Vercelへのデプロイまでの手順

アプリができたら、公開（デプロイ）する必要があります。

自分はVercelを使っています。Next.jsとの相性がいいこと、無料枠で十分使えること、GitHubと連携すると自動でデプロイされることが理由です。

手順の概要：

1. GitHubにリポジトリを作る
2. Vercelのアカウントを作る（GitHubアカウントで登録できる）
3. VercelにGitHubのリポジトリを連携する
4. 環境変数（Supabaseの接続URLなど）をVercelに入力する
5. デプロイボタンを押す

5のデプロイボタンを押してから、だいたい2〜3分で公開URLが発行されます。

「こんなに簡単なの？」と最初は拍子抜けしました。

難しいのは4の環境変数の設定です。ローカル（自分のパソコン）では`.env.local`に書いていた情報を、Vercelの管理画面に手動で入力する必要があります。ここを忘れると、デプロイは成功するけどアプリが動かない、という状態になります。

Claude Codeに「Vercelへのデプロイ手順を教えて。.env.localの設定もある」と聞くと、自分のプロジェクト構成に合わせた手順を教えてくれます。

## 非エンジニアが最初にやるべきこと

最後に、自分がもう一度やり直すとしたら何をするか、という視点でまとめます。

**Step 1：環境構築はClaude Codeに全部聞く**

Node.jsのインストールから始まり、Claude Codeのインストールまで、「Mac（またはWindows）で Claude Codeを使う環境を作りたい。手順を教えて」とそのまま聞けばいい。

**Step 2：最初のプロジェクトは「小さい完成品」を目指す**

「ユーザーが文字を入力して、送信ボタンを押したら保存される」これだけのアプリから始める。複雑なものを最初に作ろうとしない。

**Step 3：CLAUDE.mdを最初に書く**

プロジェクトを始めたらすぐに、CLAUDE.mdを作る。あとから書くより、最初から書くほうが圧倒的に楽です。

**Step 4：変更のたびにGitにコミットする**

こまめに記録することで、壊れたときに戻れる。Claude Codeが大きな変更をするとき、コミットしてから作業してもらうのがおすすめです。

**Step 5：エラーは全文コピーしてそのまま貼る**

悩む前に貼る。これが一番早いです。

---

この5ステップを知っていたら、最初の3日間の迷走はなかっただろうなと思います。

Claude Codeは、使い方を間違えると「なんか動かない」「ぐちゃぐちゃになった」という状態になりやすい。でも、ポイントを押さえると、エンジニアじゃなくても本当にアプリが作れます。

自分が実際にリリースした2本のWebアプリのうち、1本はClaude Codeをメインで使って作りました。完成までかかった時間は約30時間。Claude Codeなしだと、おそらく3〜4倍はかかっていたと思います。

試してみる価値は、確実にあります。
