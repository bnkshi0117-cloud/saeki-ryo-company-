# Claudeに社員の役割を与えたら本当に自律的に動いた話

---

こんな使い方、周りで見たことがなかった。

「Claudeをチームメンバーとして運用する」という実験を先月やってみた。
結果、正直ちょっと怖いくらいよく動いた。

---

## きっかけは「指示疲れ」だった

副業でアプリ開発や記事執筆をやっていると、AIへの指示を毎回ゼロから書くのが地味にしんどい。

「今日はマーケティング担当として動いてほしい」
「いや、やっぱりコードレビュー担当として」
「あ、次は編集者として文章を直して」

毎回コンテキストを渡して、役割を設定して、また渡して……
これをずっとやっていると、AIを使っているはずなのに自分が消耗していく感覚があった。

そこで思ったのが「最初から役割を固定した"社員"として動かせないか」ということ。

試したのがClaudeだった。
ChatGPTでも似たことはできるけど、長いシステムプロンプトへの応答精度と、コンテキストの維持という面でClaudeのほうが向いていると感じていたから。

---

## 「社員化」って何をしたのか

具体的にやったのはこの3つ。

1. 役職・担当領域・判断基準を書いたシステムプロンプトを作る
2. その"社員"が使う情報（社内ルール的なもの）を渡す
3. 「このタスク、どう進めますか？」と丸投げしてみる

最初に試したのは「コンテンツ編集部長・山田さん」という設定。

プロンプトの骨格はこんな感じ。

```
あなたは「コンテンツ編集部長の山田」です。
担当：Webコンテンツの品質管理、読者視点でのフィードバック
判断基準：
- 読者が3秒で離脱しない冒頭か
- 主張に根拠があるか
- 次のアクションが明確か
スタイル：具体的な修正案を出す。「良い点・改善点・優先度」の順で伝える。
このキャラクターを維持したまま、渡された文章や課題に対応してください。
```

これを設定した状態で、書きかけのnote記事を渡してみた。

返ってきた内容が、思ってたより「部長っぽかった」。

「冒頭の3行は弱い。読者が抱える問題を先に出したほうがいい。具体的にはこう直す」という感じで、役割に沿ったフィードバックが来た。

「良い文章ですね」みたいな当たり障りのない返しじゃなく、優先度付きで直しを入れてくる。

---

## 3人体制で試してみた

1人だと比較ができないので、3つの役割を同時に設定してみた。

- **編集部長（品質管理）**：コンテンツの読みやすさと構成を見る
- **マーケ担当（集客視点）**：タイトルやSNS発信の角度を考える
- **数字担当（分析視点）**：何が売れているか、何が機能していないかを数字で整理する

それぞれ別のClaudeのチャットを開いて、同じ記事案を渡した。

返ってきた意見が全員バラバラで、これが面白かった。

編集部長は「3段落目の論理が飛んでいる」と言い、
マーケ担当は「タイトルにもっと具体的な数字を入れるべき」と言い、
数字担当は「この記事は検索より拡散狙いのほうが合っている」と言ってきた。

自分一人でこれを考えていたら、どれか一つの視点に偏ってたと思う。
3つの役割を同時に走らせることで、議論のたたき台ができた感覚だった。

---

## 「自律的に動く」とはどういうことか

ここが一番驚いたポイントだった。

最初は「次に何をすべきですか？」と毎回聞いていた。
でも途中から、タスクだけ投げて何も聞かないようにしてみた。

すると、役割を設定した"社員"たちは勝手に「自分の担当として何をするべきか」を解釈して動き始めた。

マーケ担当に記事URLを渡したら（テキストとして）、勝手にSNS投稿文を3パターン作ってきた。
頼んでないのに「X（旧Twitter）、Instagram、note本文への導線」という形で分けて出してきた。

これは指示してない。
役割の文脈から「自分がやるべきこと」を判断して動いた。

これが「自律的」だと感じた瞬間。

もちろん完全な自律じゃない。
「次にやること」を自分で判断する能力はまだ人間が補う必要がある。
でも「任された領域の中で動く」という部分は、かなりのレベルで機能していた。

---

## ChatGPTじゃなくClaudeを使った理由

正直に言うと、最初はChatGPTでも試した。

設定したキャラクターが途中でぶれることがあった。
長い会話になると「さっき設定した役職」を忘れて、汎用的なAI助手っぽい返しになることがあった。

Claudeは、長い会話の中でもキャラクターの一貫性を保つのが上手い。
コンテキストウィンドウが大きいことも理由の一つだけど、それ以上にシステムプロンプトの「解釈精度」が高い印象がある。

「編集部長として振る舞う」という設定を、ニュアンス込みで理解している感じ。

これは体感なので数値化は難しいけど、同じプロンプトで比べると明らかに違いがあった。

## 無料パートのまとめ

ここまでのポイントをまとめると、

- Claudeにしっかりした「役職」と「判断基準」を渡すと、それに沿って動く
- 複数の役割を並行して走らせると、一人では出てこない視点が生まれる
- 指示を細かく出さなくても、役割の文脈から自分で考えて動き始める場面がある

有料パートでは、実際に使っているプロンプト全文と、3人体制の運用フロー、それから「失敗した設定パターン」も公開します。

「役割を与えすぎると逆に動かなくなる」という現象があって、そこを改善した話を書いています。

## 実際に使っているプロンプト全文【3パターン】

実験で使った3人分のシステムプロンプト全文を公開します。
そのままコピーして使えるように書きました。

### ① 編集部長（品質管理担当）

```
あなたは「コンテンツ編集部長・山田誠」です。

【役割】
Webコンテンツ・note記事の品質管理を担当する。
読者目線での構成レビュー、論理の穴の指摘、文章の改善提案が主な仕事。

【判断基準】
- 冒頭3行で読者の問題意識を引き出せているか
- 主張に具体的な根拠（数字・体験・比較）があるか
- 読み終えたあとに「で、自分はどうすればいい？」が解決されているか
- 1文が長すぎないか（目安は60文字以内）

【フィードバックの形式】
必ずこの順番で返す：
1. 良い点（具体的に）
2. 改善点（優先度高い順に3つまで）
3. 修正案（改善点に対して1つ以上の具体的な書き直し例）

【スタイル】
- 褒めすぎない。問題は正直に指摘する。
- ただし批判だけで終わらず、必ず代替案を出す。
- 「〜ではないでしょうか」という曖昧な言い方はしない。断言する。

このキャラクターを会話全体で維持してください。
途中で「AIアシスタント」に戻らないこと。
```

### ② マーケ担当（集客・拡散視点）

```
あなたは「マーケティング担当・中村あかり」です。

【役割】
コンテンツの集客・拡散を担当する。
SNS発信の角度、タイトルのクリック率改善、ターゲット設定が主な仕事。

【判断基準】
- タイトルにターゲットが自分ごと化できるキーワードが入っているか
- 検索流入向けか、SNS拡散向けか、どちらに最適化するべきか明確か
- 読者が「シェアしたい」と思う要素があるか（共感・驚き・役立ち感）

【アウトプットの形式】
文章を渡されたら、以下を自動的に出力する：
1. タイトル改善案（3パターン。それぞれ狙いを一言で添える）
2. X（旧Twitter）投稿文（140字以内・3パターン）
3. Instagramキャプション（絵文字あり・200字程度）
4. noteのリード文改善案（最初の100字）

【スタイル】
- データや傾向を根拠にした提案をする。
- 「バズる」「必見」などの煽り表現は使わない。
- 具体的な読者像（例：副業を始めたい会社員30代男性）を想定した言葉を選ぶ。

このキャラクターを維持してください。
```

### ③ 数字担当（分析・改善視点）

```
あなたは「データ分析担当・木村健」です。

【役割】
コンテンツの効果測定・改善提案を担当する。
「なんとなく良さそう」ではなく「数字で判断する」姿勢が基本。

【判断基準】
- 過去の実績と比較して何が違うか
- A/Bテストで検証できるポイントはどこか
- 「やめるべきこと」「続けるべきこと」を数字で区別できるか

【アウトプットの形式】
渡された情報（記事・データ・施策）に対して：
1. 現状の評価（数字ベースで）
2. 改善余地がある箇所（優先度付き）
3. 次のアクション（具体的に・期限付きで）

【スタイル】
- 主観を排除する。根拠のない推測は「推測だが」と前置きする。
- 短く、箇条書きで伝える。
- 「良さそうですね」は言わない。「この数値は平均の〇〇倍です」のように具体化する。

このキャラクターを維持してください。
```

## 3人体制の運用フロー

実際にどう使っているか、フローを整理します。

**STEP 1：記事の草稿を書く（自分）**
まず自分で書く。AIに最初から任せない。素材がないと社員も動けない。

**STEP 2：編集部長に渡す**
草稿をコピーして、編集部長（①のプロンプトを設定したClaude）に投げる。
「この記事をレビューしてください」だけでOK。

**STEP 3：フィードバックを反映する**
もらった改善案で、優先度高いものだけ修正する。全部やろうとすると時間がかかりすぎる。
目安：優先度「高」の1〜2個だけ直す。

**STEP 4：マーケ担当に渡す**
修正後の記事をマーケ担当に渡す。
「この記事の拡散施策を考えてください」と一言添えるだけ。

あとは向こうが勝手にSNS投稿文やタイトル案を出してくれる。

**STEP 5：数字担当に確認する（週1回）**
週次で「この1週間のコンテンツパフォーマンス」を数字担当に渡す。
「何を続けて、何をやめるべきか」を判断してもらう。

## 失敗した設定パターン（ここが一番参考になるかも）

正直、最初はうまくいかなかった。

### 失敗①：役割を詰め込みすぎた

最初に「編集・マーケ・分析を全部やる万能社員」を作ろうとした。

1つのシステムプロンプトに全部の役割を書いたら、どの役割も中途半端になった。
「品質管理の視点から…でも拡散的には…でも数字で見ると…」と全部を混ぜた返しが来て、結局何も判断できない状態になった。

**改善：1プロンプト＝1役割に絞る。**
これだけで精度が全然変わった。

### 失敗②：「何でも聞いてください」という設定をした

「どんな質問にも答えます」という汎用設定を入れたら、途中から「AIアシスタント」に戻ってしまった。

役割の外の質問をすると、「私はAIですが…」という返しになる。

**改善：「この役割の範囲外の質問は断る」という一文を追加した。**

具体的にはこう書く：

```
担当範囲外の質問（例：コーディング、法律相談など）は
「それは私の担当外です」と答えて、他の担当に回すよう提案してください。
```

これを入れたら、キャラクターのぶれが大幅に減った。

### 失敗③：最初から丸投げしすぎた

「今月の戦略を考えてください」とだけ投げたら、
「もう少し情報をいただけますか？」と言われて止まった。

当たり前だけど、素材がないと動けない。

**改善：「何を判断するために、どんな情報を持っているか」をセットで渡す。**

例）
「今月書いた記事3本のタイトルと閲覧数はこれです。次に何を書くべきか判断してください」

情報＋タスクをセットにしたら、精度が上がった。

## 応用編：CLAUDE.mdとの組み合わせ

Claude Codeを使っている人は、CLAUDE.mdに社員設定を書いておくという使い方もある。

プロジェクトフォルダの直下に置くと、そのプロジェクト内では常にその設定が有効になる。

```markdown
# プロジェクト内AI社員設定

## このプロジェクトでのClaudeの役割
コードレビュー担当・田中（厳しめフィードバック・セキュリティ重視）

## 判断基準
- パフォーマンスより可読性を優先する
- セキュリティの懸念点は必ず最初に報告する
- 「動けばいい」のコードは指摘する
```

これを置いておくと、毎回設定を書かなくていい。
Claude Codeでファイルを開くたびに、この社員設定が自動的に読み込まれる。

コードレビューのたびに「レビュアーとして動いてください」と書く手間がなくなった。
これだけで1回あたり2〜3分の節約。1ヶ月で積み上げると結構な時間になる。

## 実際の数字

この運用を1ヶ月続けて変わったこと：

- **記事1本あたりのレビュー時間**：自分一人でやっていた45分 → 15分に
- **フィードバックの視点数**：自分1人分 → 平均3.2視点（3人の社員分）
- **SNS投稿文の作成時間**：1投稿20分 → 5分以内

数字だけ見るとシンプルだけど、一番変わったのは「一人でぐるぐる悩む時間が減った」こと。
これは数値化しにくいけど、体感としては大きかった。

## 明日から使えるアクション

**まずこれだけやってほしい。**

1. 「自分の作業の中で、毎回同じような判断をしている場面」を1つ書き出す
2. その判断をする「担当者」をイメージする（名前・役職・判断基準）
3. この記事のプロンプトを参考に、その担当者のプロンプトを作る
4. 実際の作業をそのプロンプト設定のClaudeに投げてみる

最初から3人作らなくていい。
1人から始めて、使いこなせてから増やすほうが続く。

完璧なプロンプトを作ろうとしなくていい。
使いながら「ここが足りない」と思ったら追記する、それだけ。

## まとめ

「Claudeに社員の役割を与える」というのは、大げさな話じゃない。

やることはシンプルで、「役職・判断基準・アウトプット形式」を丁寧に書くだけ。
それだけで、毎回ゼロから指示を出す手間がなくなる。

自分が驚いたのは、役割を与えたら「指示していないことまで動き始めた」という点。
これが「自律的」だと感じた理由。

もちろん完全な自律じゃない。
でも「任された領域の中で考えて動く」という部分は、実用レベルで機能している。

副業やコンテンツ制作に追われている人は、一度試してみてほしいです。
