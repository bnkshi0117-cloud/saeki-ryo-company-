# エンジニアじゃない自分がClaude Codeを使って気づいたこと

---

## 最初に正直に言います

「コードが読めなくてもアプリが作れる」って、半信半疑でした。

正確には、「作れるのかもしれないけど、自分には無理だろうな」と思っていました。

でも実際にやってみたら、半分合ってて半分間違っていた。その話をします。

---

## 自分のスペックを最初に開示しておきます

沖縄で会社員をしながら副業でいろいろやっている佐伯亮です。

AI関連だとChatGPTは2022年末から使っていて、Claudeも結構長い。Kindle本を8冊出していて、Webアプリも2本リリースしました。

ただ、エンジニアではないです。

HTMLとCSSは少しわかる。JavaScriptは「なんとなく読める」くらい。Pythonは写経したことがある程度。本業はまったく別の業種の会社員です。

そういう人間がClaude Codeを触った話です。

---

## Claude Codeってそもそも何者なのか

ざっくり言うと、**ターミナルで動くAIコーディングエージェント**です。

チャット型のClaudeとは少し違います。チャット型はブラウザで会話するだけ。Claude Codeは自分のパソコンの中に入り込んで、ファイルを読んだり、コードを書いたり、コマンドを実行したりします。

初めて使ったとき、正直こわかったです。

「このAI、自分のパソコンで何してるんだろう」って。

でも動きを見ていると、やっていることはシンプルでした。

- ファイルを開いて中身を確認する
- 指示に沿ってコードを書く
- エラーが出たら読んで自分で直そうとする

人間のエンジニアがやることを、AIがやっている。それだけです。

---

## インストールしてから最初の30分で感じたこと

Claude Codeのインストール自体は難しくないです。

Node.jsが入っていることを確認して、ターミナルで`npm install -g @anthropic-ai/claude-code`を実行する。APIキーを設定する。それだけです。

ただ、「インストールできた」と「使いこなせる」は別の話でした。

最初にやったのは、既存のHTMLファイルを渡して「もっとシンプルなデザインにして」と頼むことでした。

Claude Codeはファイルを読んで、変更を提案して、承認すると書き換えてくれる。

ここで最初のカルチャーショックを受けました。

**承認のたびに自分がファイルの中身を確認していたんですが、何が変わったかすぐわからない。**

チャット型でコードを生成してもらうとき、自分でコピペするので「自分がやっている感」があります。でもClaude Codeは向こうが直接書き換える。良くも悪くも、自分の関与が薄い。

最初の30分で、「これは便利だけど、ちゃんと理解しながら使わないとまずいな」と思いました。

---

## 実際に何を作ったか

副業でやっているタスク管理の記録を、毎日テキストファイルに残していました。

そのファイルを読み込んで、「今週どのタスクに何時間かけたか」を可視化する簡単なWebアプリを作ることにしました。

使ったのは以下の構成です。

- フロントエンド：HTML + JavaScript（シンプルに）
- データ処理：Pythonスクリプト
- ホスティング：Vercel

全部で5日間、1日1〜2時間ぐらいの作業でした。

## 実際に使ったプロンプトを全部出します

最初に学んだのは、**「何を作りたいか」だけでなく「何を作りたくないか」も伝える**ことでした。

最初の指示はこうでした。

> 「毎日書いているテキストファイルがあります。形式は日付、タスク名、かかった時間の3列です。これを読み込んで、週ごとの集計を表示するシンプルなWebページを作ってください。」

これで動いてくれました。でも出てきたのは想像より複雑なUIでした。

チャート、フィルター、ソート機能まで作り始めて、「そこまで頼んでないんだけど」という状態に。

2回目からは、最後に「なるべくシンプルに。余分な機能は追加しないでください」を必ず足しました。

これだけで出てくるコードの量が半分以下になりました。

---

### うまくいった指示の型

実際に使った指示文のパターンをいくつか整理します。

**パターン1：範囲を明示する**

> 「〇〇ファイルだけを修正してください。他のファイルは触らないでください。」

Claude Codeは「関係ありそうなファイル」を自分で判断して変更することがあります。意図しない変更が起きやすいので、スコープを明示するのが大事でした。

**パターン2：ステップを分ける**

> 「まずPythonスクリプトだけ作ってください。HTMLは後で別途お願いします。」

一度に全部頼むと、どこかでエラーが出たとき原因がわかりにくくなります。1ステップずつ作って確認する流れの方が、結果的に速かったです。

**パターン3：エラーをそのまま渡す**

> 「このエラーが出ています：[エラーメッセージをそのまま貼る]。何が原因か説明してから直してください。」

「説明してから直して」を入れるのがポイントです。これがないと、何をどう変えたかわからないまま進んでしまいます。

## つまずいたポイント8つ

### 1. ターミナルが怖くて最初から躊躇した

恥ずかしながら、ターミナルをそんなに使ってこなかったです。

黒い画面に文字を打つのが、なんとなくハードルでした。

解決策は単純で、「ターミナル 基本コマンド」で調べて、`ls`、`cd`、`pwd`の3つだけ覚えました。これだけで8割は対応できました。

### 2. APIキーの料金が不安だった

Claude Codeは従量課金です。最初は「気づいたら高額請求になってるんじゃ」と心配でした。

実際の使用感として、5日間の開発で使ったAPI費用は約800円でした。開発の規模や頻度によりますが、思ったより安かったです。

Anthropicのコンソール画面で使用量をリアルタイムで確認できます。最初はこまめに確認する癖をつけるといいです。

### 3. 承認のスピードに迷った

Claude Codeは変更のたびに承認を求めます。「これ承認していいのかな」と毎回悩んでいました。

対策として、変更内容の説明文だけを読んで承認するようにしました。コード全部を読もうとすると無限に時間がかかります。「何をしようとしているか」がわかれば、細部は任せるスタンスに切り替えました。

### 4. 同じエラーを何度も直そうとする無限ループ

Pythonスクリプトで特定のエラーが出たとき、Claude Codeが何度も違うアプローチで修正しようとして、30分ぐらいループしたことがありました。

解決策は、「一度止めて、エラーの意味を自分で調べる」ことでした。調べてみると、ライブラリのバージョンの問題で、インストールし直すだけで解決しました。AIに丸投げするより、自分でエラーを理解する場面も必要だと学びました。

### 5. CLAUDE.mdの存在を最初知らなかった

Claude Codeにはプロジェクトの設定ファイルとして`CLAUDE.md`というものが使えます。

「このプロジェクトではPythonを使う」「コメントは日本語で書く」「シンプルさを優先する」など、毎回伝えなくていいルールをここに書いておくと、指示が格段に楽になります。

自分のCLAUDE.mdに書いた内容はこんな感じです。

```
# プロジェクトの概要
タスク管理データを可視化するWebアプリ

# 使用言語
- フロントエンド：HTML、JavaScript（ライブラリなし）
- バックエンド処理：Python 3.11

# 開発方針
- シンプルを最優先にする
- 外部ライブラリは最小限にする
- コメントは日本語で書く
- 1回の変更は小さく

# 注意事項
- data/フォルダは絶対に変更しない
- 既存のHTMLファイルのデザインは維持する
```

これを最初から設定しておけばよかったと思います。

### 6. バージョン管理をしていなかった

3日目に大きな変更を加えたら、それ以前の動いていた状態に戻せなくなりました。

Gitを使っていなかったのが原因です。

Claude Codeを使い始める前に、`git init`してコミットする習慣をつけることを強くすすめます。「とりあえず動いた」タイミングで必ずコミットする。これだけで安心感がまったく違います。

### 7. VercelへのデプロイでCLIとWebどちらかで迷った

Vercelへのデプロイ方法は主に2つあります。GUIのWeb画面からやる方法と、ターミナルでCLIを使う方法。

自分は最初Web画面でやろうとして、設定の場所がわからずに詰まりました。

結局Claude Codeに「Vercelにデプロイする手順を教えて」と聞いたら、CLIの手順を出してくれました。コマンド数回で済んで、こちらの方が断然早かったです。

具体的なコマンドはこうです。

```
npm install -g vercel
vercel login
vercel
```

これだけです。質問にいくつか答えるだけでデプロイ完了します。

### 8. 完成の定義を決めていなかった

これが一番の失敗でした。

「もう少し良くしたい」「この機能も追加したい」と際限なくなりました。開発を始めた当初の目的は「タスクの時間集計を見られる」だけだったのに、気づいたら検索機能やエクスポート機能まで作り始めていました。

最初に「これができたら完成」という定義を1枚の紙に書いておくことをすすめます。スコープを決めておかないと、終わりが来ません。

---

## 非エンジニアが最初にやるべき3ステップ

経験を踏まえて、「最初の1週間」でやることを整理しました。

**ステップ1：小さなものを1つ完成させる**

最初からアプリを作ろうとしないでください。

まず「既存のHTMLファイルを渡して、文字の色を変えてもらう」くらいの小さなことから始める。Claude Codeがどう動くか、承認の流れがどうなっているかを体で覚える段階です。

**ステップ2：CLAUDE.mdとGitを最初に設定する**

プロジェクトフォルダを作ったら、最初にやること2つ。

`git init`してCLAUDE.mdを作る。これだけで後の作業が3倍楽になります。

**ステップ3：「どこまで作るか」を先に決める**

作りたいものの機能を付箋に書き出す。そのうち「最初のバージョンに絶対必要なもの」だけを選ぶ。それ以外は「後でやる」フォルダに入れる。

この3ステップを守るだけで、かなりストレスなく進められると思います。

---

## 結局、何がわかったか

Claude Codeを使ってわかったのは、「コードが書けなくてもアプリは作れる。ただし、考えることは自分でやらないといけない」ということでした。

何を作るか、どこまで作るか、エラーは何が原因か。

これを考えるのは人間の仕事で、AIには代わりにできない。

逆に、「どう実装するか」「どのコードを書くか」はほとんどAIに任せられる。

エンジニアの仕事が変わっていくというのは聞いていましたが、自分が体験したのは「エンジニアじゃなかった自分の仕事の可能性が広がった」感覚でした。

完璧なものじゃなくていい。動くものを早く作って、使いながら改善する。

その進め方がClaude Codeと合っていると思います。

5日間のトータル作業時間は約9時間でした。「9時間でWebアプリが作れた」という感覚より、「9時間かければ非エンジニアでも形にできる」という手応えが今も残っています。

次は何を作ろうか、ぼちぼち考えています。
