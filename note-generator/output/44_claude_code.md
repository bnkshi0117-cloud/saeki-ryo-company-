# Claude Codeでアプリ開発が途中で止まった時の対処法

---

## 「なぜ急に動かなくなるの…」

Claude Codeで開発を進めていて、急に止まった経験はありませんか。

エラーメッセージが出ても意味がわからない。何度指示しても同じところでつまずく。昨日まで動いていたのに、今日起動しない。

これ、あるあるです。私も最初の頃は「自分の指示が悪いのか」「もうコードが壊れたのか」と毎回パニックになっていました。

でも実際に2本のWebアプリをClaude Codeで作り切ってわかったのは、**止まる理由にはパターンがある**ということ。そのパターンを知っていれば、ほとんどの場合は30分以内に再起動できます。

この記事では、私がClaude Codeで開発中に実際に経験した「止まり方の種類」と、それぞれの対処法を書きます。

---

## 自己紹介（なぜ私が書けるか）

佐伯亮といいます。沖縄在住の会社員で、副業でAI活用やアプリ開発をやっています。

プログラミングの経験はほぼゼロからスタートしました。HTML/CSSを少しかじった程度で、JavaScriptもPythonも「読めばなんとなくわかる」レベルです。

そんな状態でClaude Codeを使い始めて、Webアプリを2本リリースしました。1本目は沖縄の飲食店検索ツール、2本目は副業タスク管理のSaaSです。

どちらも開発中に何度も止まりました。最長で3日間、同じバグから抜け出せなかったこともあります。

その経験から書いているので、エンジニアの方が読むと「そんな初歩的な…」と感じる内容もあるかもしれません。でもこれは、私と同じような非エンジニアの方に向けて書いています。

---

## 「止まる」には4種類ある

Claude Codeで開発が止まる理由を、私の経験からざっくり分類すると4種類あります。

1. **Claudeが文脈を失っている**（会話が長くなりすぎた）
2. **環境が壊れている**（依存関係やパッケージの問題）
3. **指示が曖昧すぎる**（Claude側ではなく人間側の問題）
4. **そもそもの設計が間違っている**（根本的な方向性のミス）

それぞれに対処法が違います。

「なんか動かない」と感じたとき、まずどの種類かを判断することが最初のステップです。

---

## 種類①：Claudeが文脈を失っているケース

これが一番多いです。

Claude Codeは会話の流れを記憶しながら開発を進めますが、会話が長くなると**初期の設計方針や変数名、ファイル構成などを「忘れる」**ことがあります。

症状としては：

- 同じ修正を何度もしているのに、別の場所で同じエラーが出る
- 「さっきこう決めたのに」という仕様と違うコードが出てくる
- 指示しているのに、どんどん複雑な方向に進んでいく

こういう時は、**会話をリセットして文脈を再入力する**のが正解です。

最初にやってよかったのが「CLAUDE.md」というファイルを作ることです。プロジェクトのルートディレクトリに置くと、Claudeが毎回読み込んでくれます。

```
# プロジェクト概要
アプリ名：〇〇
技術スタック：Next.js + Supabase + Vercel
目的：〇〇を解決するWebアプリ
現在の状況：〇〇機能まで完成、次は△△を実装中
```

こういう内容を書いておくと、会話をリセットしても方向性がズレにくくなります。

---

## 種類②：環境が壊れているケース

これが一番つらいです。なぜなら**自分のせいじゃないのに、なぜ動かないかわからない**から。

症状としては：

- ターミナルに赤いエラーが大量に出る
- `npm install`や`pip install`が途中で止まる
- 「昨日まで動いていたのに今日は起動しない」

最初にやることは、**エラーメッセージをそのままClaude Codeに貼ること**です。

「動かないんですがどうすればいいですか？」ではなく、ターミナルに出ているエラーをそのままコピーして渡す。これだけで解決することが7割くらいあります。

私が実際に経験したのは、Node.jsのバージョン違いでアプリが起動しなくなったケースです。エラー文をそのまま渡したら「Node.jsのバージョンが対応していません。以下のコマンドで確認してください」と即座に原因を特定してくれました。

---

## 種類③：指示が曖昧すぎるケース

これは自分の問題です。正直、開発初期に一番多かったのがこれでした。

「ログイン機能を作って」という指示は曖昧です。メールとパスワードか、SNS認証か、二段階認証は必要か。セッションはどう管理するか。

曖昧な指示→Claudeが独自判断→想定と違うコードが出る→修正指示→また独自判断…というループに入ります。

対処法は**指示を分解すること**です。

「ログイン機能を作って」を渡す前に：

- 使うサービスはSupabaseのAuth
- メールアドレスとパスワードのみ
- ログイン後は/dashboardにリダイレクト
- エラー時は日本語でメッセージを表示

このレベルまで具体化してから渡すと、一発で意図通りのコードが出ることが多いです。

---

## 種類④：設計が根本的に間違っているケース

これは気づくのが一番遅れます。

症状は「何を修正しても治らない」「バグを直すと別のバグが出る」という状態です。

私が2本目のアプリ開発で経験しました。タスク管理ツールを作っていたとき、データベースの構造を最初に間違えたまま2週間開発を進めました。結果、ユーザーとタスクの紐付けが複雑になりすぎて、どこを修正しても別の場所が壊れる状態になりました。

解決策は**Claude Codeに現状分析を頼むこと**でした。

「このプロジェクトの現在の構造を確認して、問題点を教えてください」と渡したら、データベース設計の根本的な問題を指摘してくれました。その後、設計を一部やり直すことで、それまで3日かかっていた機能が半日で実装できました。

---

## 無料パートのまとめ

Claude Codeで開発が止まったとき、まず「どの種類の止まり方か」を判断することが大事です。

- 会話が長くなってきた → CLAUDE.mdで文脈を整理
- エラーが出ている → エラーメッセージをそのまま渡す
- 何度修正しても直らない → 指示を具体化する
- バグが連鎖している → 設計から見直す

この4つを把握しているだけで、「詰まり続ける時間」がかなり減りました。

有料パートでは、**私が実際に使った指示文（プロンプト）の具体例**と、**詰まった時に必ず試す5つの手順**を公開します。

特に「Claudeが同じミスを繰り返す」ときの対処法は、これを知っているかどうかで開発速度が変わります。

## 有料パート：実際に使った指示文と、詰まりを抜ける5つの手順

### なぜ有料パートで公開するか

正直なところ、ここに書く内容は「コツ」というより「試行錯誤の結晶」です。

私が2本のアプリを作る中で、何十時間も詰まった末に見つけたパターンです。先に知っていれば、1本目のアプリ開発は2ヶ月かかったところを1ヶ月以内に終わっていたと思います。

同じ時間を使わなくて済むように、具体的に書きます。

---

### 詰まりを抜ける5つの手順

**手順1：まず「現状確認モード」に入る**

止まったとき、最初にやることは「現状を言語化すること」です。

```
現在の状況を整理します。
・実装しようとしていた機能：〇〇
・出ているエラー：（エラー文をここに貼る）
・直前にやった操作：〇〇のファイルを変更した

このエラーの原因として考えられることを3つ挙げてください。
修正の前に、原因の確認をしたいです。
```

このプロンプトを渡すと、Claudeが「一気に修正しよう」モードではなく「まず確認しよう」モードになります。

私の経験では、この確認ステップを入れるだけで、修正が一発で決まる確率が上がりました。感覚値ですが、確認なしで直させると3〜4回かかるところが、確認ありだと1〜2回で終わることが多いです。

---

**手順2：エラーを「翻訳」させる**

エラーメッセージを読んでもわからないとき、多くの人は「なんか動きません、直してください」と渡します。

でもこれは遠回りです。

```
以下のエラーメッセージを日本語で説明してください。
エラーの意味と、考えられる原因を教えてください。
修正はまだしなくて大丈夫です。

（エラーメッセージを貼る）
```

「修正はまだしなくて大丈夫です」という一文が重要です。

これを入れないと、Claudeはすぐコードを変更しようとします。原因を理解する前に修正されると、「なぜ直ったのか（あるいはなぜ直らないのか）」がわからなくなります。

理解→修正の順番を守ることで、同じエラーが次に出たときに自分で対処できるようになります。

---

**手順3：ファイルの全体像を確認させる**

3日間詰まっていた経験の中で気づいたのが、「Claudeは今何があるかを把握していないことがある」ということです。

特に会話が長くなってくると、どのファイルが存在して、何が書いてあるかを正確に把握できていない状態になります。

```
現在のプロジェクトのファイル構成を確認してください。
主要なファイルの役割を簡単に説明してください。
その後、今の問題に関係しているファイルはどれか教えてください。
```

これを渡すと、Claudeが「あ、このファイルを見落としていました」となることがあります。

私の2本目のアプリ開発では、このプロンプトで「auth.jsというファイルが存在していますが、現在のコードから呼び出されていません。これが原因の可能性があります」と指摘されました。1週間解決できなかった問題が5分で特定されました。

---

**手順4：「逆順」で指示する**

「〇〇を実装してください」という指示が曖昧なとき、私がよく使うのが「逆順指示」です。

```
〇〇機能を実装する前に、以下を教えてください。

1. この機能に必要なファイルは何ですか？
2. 修正が必要な既存のコードはありますか？
3. 実装の手順を番号で教えてください。

手順を確認したら、私がOKと言ってから実装してください。
```

これを入れることで、「やってみたら全然違う方向だった」という事態を防げます。

特に「私がOKと言ってから実装してください」という一文は効果的です。計画を確認してからGOサインを出す習慣をつけると、無駄な修正作業が減ります。

---

**手順5：コンテキストをリセットして再スタートする**

手順1〜4を試してもどうしても抜け出せないとき、私は会話をリセットします。

長時間詰まっているとき、会話の中に「誤った前提」や「矛盾する指示」が積み重なっていることがあります。リセットして新鮮な状態で始めた方が早く解決することが多いです。

リセット前にやること：

```
これまでの経緯をまとめてください。
・実装しようとした機能
・今の問題の状況
・試したこと
・現在のコードの状態

このまとめをメモしておきます。
```

この「引き継ぎメモ」を作ってからリセットすると、新しい会話でゼロから説明し直す手間が省けます。

### CLAUDE.mdの書き方テンプレート

CLAUDE.mdに書いておくと特に効果が高い内容を共有します。

```markdown
# プロジェクト名：〇〇

## 概要
（アプリが何をするものか、一文で）

## 技術スタック
- フロントエンド：Next.js 14
- バックエンド：Supabase
- デプロイ：Vercel
- スタイリング：Tailwind CSS

## ディレクトリ構成
- /app：ページファイル
- /components：共通コンポーネント
- /lib：ユーティリティ関数
- /types：TypeScript型定義

## コーディングルール
- コメントは日本語で書く
- エラーメッセージは日本語で表示する
- コンポーネント名はパスカルケース

## 現在の状況
（毎回ここを更新する）
- 完成している機能：〇〇、〇〇
- 現在対応中：〇〇
- 次にやること：〇〇

## 既知の問題
（現在わかっているバグや課題を書く）
- 〇〇のページでたまに△△が起きる
```

### 最後に：詰まることは「普通」です

Claude Codeで開発が止まることは、誰でもあります。エンジニアでも起きます。

大事なのは「詰まった時にどう動くか」のパターンを持つことです。

私がこの記事に書いた手順を身につけてから、1日中同じバグで消耗するということがほぼなくなりました。2〜3時間以内には必ず「次の一手」が見つかるようになっています。

非エンジニアがClaude Codeで開発するのは、間違いなく今がやりやすい時代です。詰まりながらでも前進できるなら、アプリは必ずリリースできます。

一緒に作りましょう。
