# noteの有料記事をAIで書いたら売れたか正直に報告する

---

「AIで記事を書けば簡単に稼げる」って聞いて、やってみた人間の話です。

結論から言うと、売れました。でも思っていた感じとは違いました。

何がどう違ったのか、数字と体験をそのまま書きます。

---

## なぜnoteの有料記事をAIで書こうと思ったか

僕は沖縄で会社員をしながら副業でKindle出版とアプリ開発をやっています。

Kindleは8冊出していて、そこそこ売れている本もある。ただKindleは「作って終わり」じゃなくて、定期的に新刊を出し続けないと収益が落ちてきます。

それと並行でnoteもやっていましたが、無料記事ばかりで有料にするのをずっと後回しにしていました。

理由は単純で、「ちゃんと書かなきゃ」というプレッシャーがあったから。

有料記事って、お金をもらう以上は手を抜けない気がして、なかなか手が動かない。結果、下書きフォルダに5本くらい眠らせたまま放置していました。

そんな状態のとき、試しにChatGPTで下書きを作ってみたら、2時間かかっていた作業が30分くらいで終わった。それが去年の話です。

そこから「じゃあ有料記事もAIで書いてみるか」という実験が始まりました。

---

## AI記事を出す前に考えたこと

最初に悩んだのは、「AIで書いた記事を有料で出していいのか」という倫理的な部分です。

これは正直今もグレーだと思っています。

ただ自分の中で決めたルールがあります。

- 自分が経験していないことは書かない
- AIが生成した文章を、自分の言葉で全部チェックして直す
- 「AIが書きました」という体裁の記事は出さない

要するに「AIは下書きツール」という位置づけにしました。

料理で言うと、食材の下処理はAIにやってもらって、味付けと盛り付けは自分でやる感じです。

このルールを決めてから、罪悪感なく作業できるようになりました。

---

## 実際の制作フロー

最初に出したのは、Kindle出版の手順を書いた記事でした。

テーマを選んだ理由は「自分が一番詳しいこと」だから。AIに頼るとしても、内容の正確性を担保できるのは自分の経験がある分野だけです。

制作フローはこんな感じでした。

**①構成を自分で決める（30分）**
見出しと「何を書くか」のメモをざっくり作る。ここだけは絶対に自分でやります。

**②ChatGPTに下書きを書かせる（20分）**
見出しとメモをプロンプトに渡して、各セクションの文章を生成。

**③自分で全文を書き直す（60〜90分）**
生成された文章を見ながら、自分の言葉に直していく。体験談や数字は自分で追加。

**④公開前チェック（20分）**
読み返して、「自分が言いそうにない言い回し」を削る。

合計すると2〜2.5時間です。

以前は同じ分量を書くのに5〜6時間かかっていたので、体感で半分以下になりました。

## 最初の記事、売れたのか

最初の有料記事は980円で出しました。

公開してから3日間は1本も売れませんでした。正直焦りました。

「やっぱりnoteって難しいんだな」と思いながら、SNSで少し宣伝したら4日目に1本売れた。

その後は口コミなのか検索なのかわからないまま、じわじわと売れていきました。

1ヶ月の売上は7本でした。7×980円で6,860円。

多いかどうかで言えば、多くはないです。でも「ゼロだったものがゼロじゃなくなった」という感覚が予想以上に嬉しかった。

労働時間で換算すると、制作に2.5時間かかったので、追加で宣伝に使った時間を含めても5時間くらい。時給換算で1,372円です。

沖縄の最低賃金より少し高いくらい、という感じです（笑）。

## 3ヶ月やってわかったこと（無料パート）

3ヶ月で合計4本の有料記事を出しました。

売れ方の差が激しくて、1本目は7本、2本目は2本、3本目は21本、4本目は5本という結果でした。

3本目が突出して売れた理由は、後から分析してわかりました。その話は有料パートで詳しく書きます。

ここで言えるのは「AIで書いたから売れる・売れない」ではなかったということです。

売上を左右したのは、構成とテーマ選びでした。AIはあくまで道具です。

「どのテーマを選ぶか」と「どんな構成にするか」は、AIには判断できません。ここが人間の仕事だと実感しました。

## 「AIで書いたらバレるんじゃないか」問題

これも気になっていた点です。

読者からのコメントやDMで「AI感がある」と言われたことはありませんでした。

むしろ「等身大で読みやすい」というコメントをいただくことが多い。

おそらく、③の「全文を書き直す工程」が効いていると思います。

AIの文章ってわかりやすい特徴があって、「まず〇〇について解説します」みたいな丁寧すぎる接続詞が多い。あと一文が長くなりがちです。

それを全部自分のリズムに直すと、AI感がかなり薄れます。

僕の書き方は基本的に一文を短く切るので、そのスタイルに合わせて直せばかなり「自分の文章」になります。

- 月収の推移と今後の目標
- 再現性を高める「有料記事の設計テンプレート」

「自分も有料記事を出してみたい」という方に、そのまま使えるレベルで書きました。

## 3本目が21本売れた理由

答えから言うと、「読者が検索するキーワードで書いた」からです。

1本目と2本目は「自分が書きたいこと」でテーマを選んでいました。Kindle出版の手順、AI活用の工夫、みたいな内容です。

3本目を書くとき、少し考え方を変えました。

「自分がnoteで何か買うとしたら、どんな疑問を解決したいか」という視点でテーマを選んだんです。

そこで出てきたのが「ChatGPTで副業を始めるとき、最初にやることが全然わからない」という疑問でした。

自分が1年前に持っていた疑問です。

このテーマで書いた記事が3本目です。タイトルに「最初の1週間でやること」という具体的な期間を入れて、「具体的な手順」を前面に出しました。

売れた理由を後から分析すると、

- 悩んでいる人が多いテーマだった
- 「最初の1週間」という具体的な時間軸が刺さった
- 無料パートで「あ、この人わかってる」と思ってもらえた

この3つが重なった結果だと思います。

逆に2本目が2本しか売れなかった理由は、テーマが漠然としていたことです。「AIライティングのコツ」というタイトルで出しましたが、「誰の、どんな悩みを解決するのか」が曖昧でした。

**テーマ選びの判断軸**

有料記事のテーマを選ぶとき、僕は今こうやって判断しています。

- 「1年前の自分が知りたかったことか」→ YES なら進める
- 「タイトルを見て、誰が読むかイメージできるか」→ YES なら進める
- 「自分の体験談で肉付けできるか」→ YES なら進める

3つとも YES じゃないと書かないようにしました。

## 実際に使っているプロンプト

下書き生成に使っているプロンプトをそのまま公開します。

---

```
あなたはnoteに有料記事を書くライターのアシスタントです。

以下の情報をもとに、記事の各セクションの下書きを書いてください。

【記事タイトル】〇〇

【ターゲット読者】〇〇に悩んでいる、AIを使い始めたばかりの会社員

【各セクションの見出しと書く内容のメモ】
・見出し1：〇〇（ここに書くべき内容のメモ）
・見出し2：〇〇（ここに書くべき内容のメモ）
（以下同様）

【文章のスタイル】
- 一文は60文字以内
- カジュアルなです・ます調
- 体験談ベースで書く（体験談の内容は私が後で追加するので、[体験談を追加]というプレースホルダーを置いてください）
- 数字は[数字を追加]というプレースホルダーにしてください

出力形式：Markdown
```

---

このプロンプトのポイントは「プレースホルダー」です。

体験談と数字の部分はAIに書かせない。自分が後で入れる前提で、場所だけ確保してもらう形にしています。

こうすることで、AIが「それっぽい体験談」を作り上げるのを防げます。

実際の体験談や数字が入ることで、記事の信頼性が上がります。読者が「この人は実際にやってる」と感じてくれる部分はここです。

Kindleと同じで、「作り続ける」ことが大事だと体感しています。

## 失敗した2本目の反省と改善策

2本目の「AIライティングのコツ」という記事が2本しか売れなかった原因を深掘りします。

無料パートを読み返すと、「AIを使えばライティングが楽になります」という話が続いていて、読者が「で、何が解決するの？」と感じたと思います。

無料パートの役割は「この人の有料記事を買えば、自分の悩みが解決する」と思ってもらうことです。

「知識の共有」じゃなくて「悩みの解決」が軸になっていないと、有料パートまで読み進んでもらえない。

改善策としてやったことは、無料パートの冒頭を「悩みの言語化」から始めることです。

「こんな悩みを持っていませんか？」という問いから入って、「自分のことだ」と感じてもらう。それができると離脱率が下がります。

2本目の反省から3本目では無料パートを完全に書き直しました。冒頭の3行を「読者の悩みを代弁する文章」に変えた結果が、21本という数字に繋がったと思っています。

## 有料記事の設計テンプレート

最後に、僕が毎回使っている設計テンプレートを共有します。

記事を書く前にこれを埋めると、構成がブレません。

---

**【有料記事設計シート】**

```
①ターゲット読者
→ 「〇〇に悩んでいる、△△な人」と具体的に書く

②その読者が抱えている悩み（一言で）
→ 記事を読む前の状態

③記事を読み終わった後の状態
→ 何ができるようになるか / 何が解決するか

④無料パートで伝えること
→ 「悩みへの共感」と「解決できる予感」を伝える
→ 答えは出さない

⑤有料パートで伝えること
→ 具体的な手順 / 失敗談と改善策 / 使えるテンプレート

⑥タイトルのチェック
→ 誰が読むか一目でわかるか？
→ 「知りたい情報がここにある」と感じてもらえるか？
```

---

このシートを埋めてから制作を始めると、AIへの指示も明確になります。

プロンプトに「ターゲット読者：〇〇に悩んでいる△△な人」と書けるので、生成される文章のズレが少なくなります。

## まとめ：AIで有料記事を書くことについての結論

3ヶ月やってみた正直な感想です。

AIは「書く時間を短縮する道具」としては本当に役立ちます。5〜6時間かかっていた作業が2〜3時間になる。これは体感として確かです。

ただ「AIが代わりに売れる記事を作ってくれる」わけではありません。

テーマ選び、構成、体験談の質——ここは完全に人間の仕事です。

逆に言えば、この3つをちゃんとやれば、AIを使っても使わなくても売れる記事は書けます。AIはその作業スピードを上げるものです。

これから有料記事を始めたい人へ。

最初の1本は「1年前の自分が知りたかったこと」で書いてみてください。それが一番テーマとして強いです。

売れるかどうかは出してみないとわからない。でも出さないことには何もわかりません。僕も最初の3日間は1本も売れなくて焦りました。それでもそのまま続けてよかったと思っています。
