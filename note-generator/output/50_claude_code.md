# Claude Codeで作ったアプリを収益化するまでの全記録

---

## コードが書けなくてもアプリは作れる（本当に）

「また失敗するかも」

そう思いながら、最初のコマンドを打った夜のことを今でも覚えています。

沖縄の自室。夜の11時。ターミナルの画面を前に、正直半信半疑でした。それまでに2回、アプリ開発を途中で諦めた経験があったので。

でも今回は違いました。Claude Codeと一緒に作ったWebアプリが、3ヶ月後に初めて課金ユーザーを獲得したんです。金額は月2,800円。小さな数字ですが、自分で作ったものがお金になった瞬間は、本当に震えました。

この記事は、その一部始終の記録です。

---

## 自己紹介：エンジニアじゃないけど、諦めてもいなかった

会社員をしながら副業でいろいろやっています。Kindle本を8冊出版して、ChatGPTやClaudeの使い方を発信して、ちょこちょこWebアプリも作ろうとしていました。

「しようとしていた」が正しい。実際には全部途中で終わっていました。

JavaScriptのコードがエラーで止まる。Stack Overflowで調べても解決しない。友人のエンジニアに聞くのも毎回申し訳ない。そのループで2本のアプリが放置フォルダに眠っています。

プログラミングを本格的に学ぼうとしたこともあります。Progateを2週間、Udemyのコースを1ヶ月。基礎は少し理解できたけど、「自分の作りたいものを作る」には程遠かった。

Claude Codeを試したのは、そんな状況でした。

---

## Claude Codeって何が違うの？

ここで少しだけ説明させてください。

Claude Codeは、AIがターミナル上でコードを直接書いてくれるツールです。普通のChatGPTやClaudeとの違いは、「コードを書いてくれる」だけじゃなく、「ファイルを作って、実行して、エラーを直して、また実行する」という一連の作業をAIが自律的にやってくれること。

いわゆるAIエージェントです。

以前の使い方は「コードを聞く→コピペ→エラー→また聞く→コピペ→またエラー」という繰り返しでした。Claude Codeは、その繰り返しをAI側が引き受けてくれます。

私が最初に感じた違いは、「エラーで止まらない」ということでした。

以前は「TypeError: Cannot read property of undefined」みたいなエラーが出るたびに作業が止まっていました。Claude Codeは、エラーが出たら自分でエラーログを読んで、修正して、再実行します。私はその間、コーヒーを飲んでいればいい。

もちろん全部うまくいくわけじゃないけど、それでも以前とは全然違いました。

## 作ったアプリ：沖縄在住者向けの副業マッチングツール

何を作ったかというと、「沖縄在住のフリーランス・副業人材と、地元企業をつなぐ簡易マッチングツール」です。

規模は小さいです。機能は3つだけ。

- プロフィール登録（スキル・単価）
- 案件投稿（企業側）
- 簡易メッセージ機能

沖縄って、副業・フリーランスのマッチングプラットフォームが少ないんです。クラウドワークスやランサーズはあるけど、「沖縄の企業と沖縄の人」を結ぶに特化したものがない。自分がほしいと思っていたサービスを作りました。

技術スタックはこうです。

- フロントエンド：React（Claude Codeが選択）
- バックエンド・DB：Supabase
- デプロイ：Vercel
- 認証：Supabase Auth

全部、自分で選んだわけじゃないです。Claude Codeに「こういうものを作りたい。初心者でもメンテしやすい構成にして」と伝えたら、提案してくれたものをそのまま使いました。

## 最初の2週間：動くものができた

ここから、実際の開発の話をします。

Claude Codeを入れたのは平日の夜。インストール自体は15分で終わりました。最初のプロンプトはこれです。

「沖縄在住のフリーランスと地元企業をつなぐ、シンプルなマッチングWebアプリを作りたいです。主な機能はプロフィール登録、案件投稿、メッセージ機能の3つ。Supabaseを使って、Vercelにデプロイできる構成にしてください。初心者でもわかりやすいファイル構成でお願いします」

Claude Codeはまず、ファイル構成の提案から始めました。そして一つずつファイルを作り始めた。

最初の30分で、ローカル環境でページが表示されました。

「え、もう動いてる？」

正直、信じられなかったです。もちろんUIはシンプルで、機能も半分も実装されていない状態でしたが、画面が出た。それだけで感動しました。

1週目は毎晩2時間くらい作業しました。指示を出して、動作確認して、また指示を出す。このサイクルです。

つまずいた場面も当然ありました。Supabaseのテーブル設計でエラーが出続けた2時間は、さすがに「また無理か」と思いました。でも最終的にClaude Codeが「RLSポリシーの設定が必要です」と教えてくれて、そのまま修正までやってくれた。

2週間後、ローカルで3つの機能が全部動く状態になりました。

## 3週目〜1ヶ月目：デプロイと最初の壁

ローカルで動いても、公開しないと意味がない。

Vercelへのデプロイは、想像より簡単でした。GitHubにpushして、Vercelを連携するだけ。30分かかりませんでした。

ただ、デプロイしてから問題が出ました。

ローカルでは動いていた認証機能が、本番環境でエラーになる。環境変数の設定漏れでした。SupabaseのURLとAPI keyをVercelの設定に入れ忘れていた、それだけのことですが、原因がわかるまで1時間かかりました。

Claude Codeに「デプロイしたらログインができなくなりました。エラーはこれです」と貼り付けたら、5分で解決策を出してくれました。

この経験で学んだのは、「エラーをそのまま貼る」という習慣です。エラーメッセージを自分で解釈しようとしない。そのまま渡す。それだけで解決が早くなります。

公開URL ができたあと、知り合い5人に使ってもらいました。フィードバックは正直で、「登録フローがわかりにくい」「スマホで崩れる」という指摘をもらいました。

この修正に2週間かかりました。UIの調整は、機能開発より時間がかかる。これは想定外でした。

## 2ヶ月目：収益化の設計

使えるものはできた。次は「どうやってお金にするか」です。

最初、全機能無料で公開していました。登録者は20人ほど来てくれましたが、お金は0円。当然です、有料機能がなかったので。

収益化の方法を考えて、こういう設計にしました。

- 無料プラン：プロフィール登録・案件閲覧のみ
- 有料プラン（月980円）：案件投稿・メッセージ機能

案件を出す企業側に課金してもらう形にしました。フリーランス側は無料。人が集まらないと価値がないので、まずは登録者を増やすほうを優先しました。

決済はStripeを使いました。ここが一番複雑でした。

Claude Codeに「Stripeで月額サブスクリプションを実装したい」と伝えると、Webhook、サブスクリプション管理、キャンセル処理まで含めたコードを出してくれました。ただ、Stripeの設定（ダッシュボード側の操作）は自分でやる必要があって、その部分が少しわかりにくかった。

実装に丸3日かかりました。

有料プランを実装してから3週間後、最初の課金が入りました。

通知が来た時、スマホを持ったまま固まりました。

金額は980円。でも980円以上の意味がありました。自分が0から作ったものを、知らない誰かが「使いたい」と思ってお金を払ってくれた。それが初めて起きた瞬間でした。

その後、3ヶ月の合計でこうなりました。

- 有料ユーザー（企業側）：3社

もうけは出ていないです。Claude Codeの利用料、Supabaseのプラン、ドメイン代を合わせると毎月5,000円ほどかかっています。

でも「赤字のうちは失敗」とは思っていないです。これは最初の3ヶ月。ユーザーが使ってくれるものが存在していて、少しずつ有料化が進んでいる。それが今の状態です。

## 有料パート①：実際に使ったプロンプト全公開

### 最初のプロンプトの型

最初の指示が一番重要です。ここで設計がブレると、あとから修正するのが大変になります。

私が使った型はこれです。

```
【作りたいもの】
（サービスの概要を2〜3行で）

【主な機能】
・機能1
・機能2
・機能3

【使う人】
（ターゲットユーザー）

【技術的な条件】
・初心者でもメンテしやすい構成
・SupabaseとVercelを使う
・認証あり

【まず最初にやること】
プロジェクトのフォルダ構成と、最初に作るファイルを教えてください
```

「まず最初にやること」を最後に書くのがポイントです。全部一気にやらせようとすると、出力が大きくなりすぎて途中でミスが増えます。最初は構成を確認してから、機能ごとに進める。

### 機能を追加するときのプロンプト

基本形はこれです。

```
現在の状態：（何ができているか）
追加したい機能：（具体的に）
使っている技術：（React、Supabaseなど）
気をつけてほしいこと：（既存の部分を壊さないでほしい、など）
```

「気をつけてほしいこと」を入れるだけで、既存コードへの影響が減りました。

実際に使った例をいくつか載せます。

**メッセージ機能を追加したとき：**
```
現在の状態：プロフィール一覧と案件投稿ができています
追加したい機能：ユーザー同士がシンプルなメッセージをやり取りできる機能
使っている技術：React、Supabase（realtime機能は使わず、リロードで更新でOK）
気をつけてほしいこと：既存のルーティングを壊さないようにしてください
```

**Stripe実装のとき：**
```
現在の状態：ユーザー登録・ログインができています。Supabaseのusersテーブルにis_premiumというbooleanカラムがあります
追加したい機能：Stripeで月額980円のサブスクリプション決済。支払い成功後にis_premiumをtrueにする
使っている技術：React、Supabase、Node.js（APIルートなし）
気をつけてほしいこと：Stripe Webhookを使ってis_premiumを更新する実装にしてください
```

## 有料パート②：詰まった10のポイントと解決策

### 1. Supabase RLSのエラー

「permission denied for table xxx」というエラーが何度も出ました。

原因はRow Level Security（RLS）の設定です。Supabaseはデフォルトでテーブルへのアクセスを制限します。

解決策：まずClaude Codeに「このエラーが出ています。RLSの設定を一通り確認・修正してください」と伝える。その後、Supabaseダッシュボードで「Authentication → Policies」を見て、追加されたポリシーを確認する。

### 2. 環境変数が本番で効かない

「ローカルでは動くのに、Vercelにデプロイしたら動かない」の大半はこれです。

.envファイルに書いた環境変数は、Vercelには反映されません。Vercelのダッシュボードの「Settings → Environment Variables」に同じ内容を入力し直す必要があります。

解決策：デプロイのたびに、環境変数リストを一覧化する習慣をつける。Claude Codeに「このプロジェクトで必要な環境変数を全部リストアップして」と聞くと、まとめてくれます。

### 3. Stripeのwebhookが届かない

ローカルでテストするとき、StripeのWebhookはそのままでは受け取れません。

解決策：Stripe CLIを使う。Claude Codeに「StripeのWebhookをローカルでテストする方法を教えて」と聞くと、そのままコマンドを出してくれます。「stripe listen --forward-to localhost:3000/api/webhook」が基本コマンドです。

### 4. Reactのルーティングでリロードすると404

Vercelにデプロイした後、ページをリロードすると404になる現象。

解決策：vercel.jsonというファイルをプロジェクトのルートに作る。内容はClaude Codeに聞くと出してくれます（SPAのルーティング設定です）。

### 5. スマホで崩れる

PCでは綺麗なのに、スマホで見ると崩れる。これは毎回起きます。

解決策：修正指示のときに「スマホ（375px幅）でも正しく表示されるようにしてください」を毎回付け加える。最初から言っておくと、後の修正が減ります。

### 6. ログイン状態がページ遷移で消える

Supabase Authを使っているとき、ページを移動するとログインが切れる現象。

原因：セッションの管理コードが入っていない。

解決策：「SupabaseのセッションをReactのContextで管理するコードを実装してください」と指示する。

### 7. 画像のアップロードが動かない

Supabase StorageでStorageのpolicyを設定し忘れていることがほとんどです。

解決策：「Supabase Storageで画像アップロードができません。エラーはこれです（貼り付け）。ダッシュボードで設定すべき内容と、コードの修正点を教えてください」と聞く。

### 8. デプロイのたびにビルドエラー

package.jsonのdependenciesとdevDependenciesの分類ミスが原因のことが多いです。

解決策：「Vercelでビルドエラーが出ています。エラーログはこれです（貼り付け）。原因と修正方法を教えてください」と聞く。

### 9. Claude Codeが途中で止まる

長い作業の途中でClaude Codeが「続けましょうか？」と聞いてくることがあります。そのまま「はい」で進めると、前の文脈を引き継げないことがある。

解決策：大きな機能を実装するときは、最初に「この機能を5つのステップに分けて、一つずつ進めてください」と指定する。

### 10. 何を指示すればいいかわからなくなる

これが一番よく起きます。エラーの原因がわからない、どこを直せばいいかわからない。

解決策：「現在の状態を整理してください。何が動いていて、何が動いていないか、考えられる原因は何か」と聞く。Claude Codeが現状を整理してくれます。それを見てから次の指示を出す。

## 有料パート④：3ヶ月やってみてわかったこと

正直に書きます。

**うまくいったこと**
最初のMVP（最小限の動くもの）を2週間で作れたこと。以前は2ヶ月かけても完成しなかった。この差は、「エラーで止まらない」というClaude Codeの特性が大きかったと思います。

**予想と違ったこと**
UIの調整が一番時間がかかりました。機能を作るより、「使いやすくする」ほうが難しい。Claude Codeは「動くコード」を作るのは得意ですが、「使いやすいデザイン」は人間が方向性を決める必要があります。

**最初に戻れるなら変えること**
最初からモバイルファーストで作ること。「後でスマホ対応しよう」と思っていたら、直しが大量に発生しました。最初の指示に「スマホ優先で作ってください」と入れるだけで違ったと思います。

**収益化について**
3ヶ月で月2,940円。まだ赤字です。でもここから増やす道筋は見えています。有料ユーザーに直接ヒアリングして、欲しい機能を追加して、価格を上げるか件数を増やすか。普通のビジネスと同じです。

Claude Codeが「アプリを作る壁」を下げてくれたのは本当です。でも「売れるアプリを作る壁」は別の話です。ユーザーを集めること、使い続けてもらうこと、お金を払ってもらうこと。それは自分で考えるしかない。

ただ、考える時間が増えた。開発で詰まる時間が減った分、「誰に使ってもらうか」「何が価値か」を考える時間が増えました。それが一番の変化かもしれないです。
