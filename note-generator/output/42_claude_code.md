でも今、沖縄の自宅で副業として作ったSaaSが動いています。月に数人のユーザーが使ってくれています。コードは、ほぼ自分では書いていません。

これは、その記録です。

## 自己紹介：非エンジニアの会社員です

佐伯亮といいます。沖縄在住の普通の会社員です。

プログラミングの経歴を正直に書きます。

- HTMLを少しだけ触ったことがある（20代前半）
- PythonのHello Worldは書ける
- JavaScriptのforループで詰まるレベル

それが自分の実力です。エンジニアではありません。

ただ、ChatGPTやClaudeを使い始めてから、AIを「道具」として使うのが得意になってきた感覚がありました。Kindle本を8冊出版したのも、AIと一緒に書いたからです。

「アプリ開発もAIと一緒にできるんじゃないか」

そう思い始めたのが、Claude Codeを試すきっかけでした。

## Claude Codeって何？という話

Claude Codeは、Anthropicが出したコーディング特化のAIエージェントです。

ターミナル（黒い画面）から使うCLIツールで、ざっくり言うと「AIにコードを書いてもらいながら、ファイルの作成・編集・実行まで一緒にやってくれる」というものです。

ChatGPTとの違いを聞かれたら、こう答えます。

ChatGPTはコードを「提案」してくれます。でもコピペして自分で動かす作業は自分でやらないといけない。Claude Codeは「実際にファイルを触って」くれます。

「このコードをapp.pyに書いて」と指示したら、本当にapp.pyを作ってコードを書いてくれます。それがClaude Codeの感覚です。

ただ、最初に正直に書いておきます。

**使いこなすのは簡単ではありませんでした。**

「ターミナルって何？」「npmって何？」という状態からスタートしたので、最初の1週間は環境構築だけで終わりました。

それも含めて、順番に書いていきます。

## 作ったもの：何を作ったのか

今回作ったのは、**フリーランス向けの請求書・案件管理ツール**です。

社内で副業している同僚が「Excelで案件管理してるけど、請求書の作り方がわからなくて毎月困ってる」と言っていたのがきっかけでした。

既存のツールはあります。freeeとか、misocaとか。でも無料プランだと機能が足りなくて、有料プランは月1,000円以上する。

「シンプルな機能だけ使いたい人向けのツール」があれば需要あるかも、と思いました。

技術スタックはこうなりました（後述しますが、Claude Codeに相談しながら決めました）。

- フロントエンド：React + TypeScript
- バックエンド：Supabase
- デプロイ：Vercel
- 決済：Stripe

4ヶ月かかりました。週末の2〜3時間を使って、合計100〜120時間くらいだと思います。

これを見て「npmって何？」となりました。

インストールできても、次の壁があります。

「claude」とターミナルに打ち込んで起動しても、最初は何をどう指示すればいいかわからない。ChatGPTとは操作の感覚が違います。

ここで心が折れかけました。

でも、ここを乗り越えると世界が変わりました。

## CLAUDE.mdという「設計書」の話

Claude Codeを使い始めてから、一番大事だと感じたのはCLAUDE.mdというファイルの存在です。

プロジェクトのフォルダに「CLAUDE.md」というファイルを置くと、Claude Codeが最初に読み込んでくれます。「このプロジェクトのルールや背景情報」を書いておく場所です。

最初はこれを知らずに使っていました。

毎回、「これはフリーランス向けの請求書管理ツールで、使っているのはReactとSupabaseで…」という説明を最初からしていました。これが面倒で、指示のたびにブレが生まれていました。

CLAUDE.mdを作ってからは、体感として指示の精度が上がりました。

「ログイン機能を追加して」と一言打つだけで、プロジェクトの構成を理解した上で実装してくれるようになりました。

これは後で詳しく書きますが、Claude Codeを使うなら最初にCLAUDE.mdを書くことを強くすすめます。

## 正直なところ：Claude Codeで全部はできない

誤解してほしくないので書きます。

Claude Codeは「コードを全部書いてくれる魔法のツール」ではありません。

「どんなアプリを作るか」を決めるのは自分です。「何が問題でどう解決するか」を考えるのも自分です。エラーが出たとき、原因を特定するために調べるのも自分です。

特に、エラーの解決に時間がかかりました。

Stripeの決済連携をしようとしたとき、コードは書いてくれましたが、Stripeの管理画面の設定方法はClaudeは知りません（最新情報に追いついていないこともある）。ドキュメントを読む作業は自分でやりました。

4ヶ月の開発のうち、純粋にClaudeとのやり取りに使った時間は全体の40〜50%くらいだと思います。残りは調べものや設定作業、テストに使っていました。

それでも、ゼロから自分でコードを書くよりは圧倒的に速かったと感じています。

以下が、自分が実際に使ったCLAUDE.mdの内容です。

```markdown
# プロジェクト概要
フリーランス向けの案件・請求書管理ツール。
シンプルな機能に絞り、無料〜月480円で提供する。

## 技術スタック
- フロントエンド：React 18 + TypeScript
- スタイリング：Tailwind CSS
- バックエンド：Supabase（認証・DB）

## ディレクトリ構成
- /src/components : UIコンポーネント
- /src/pages : ページコンポーネント

## コーディングルール
- コンポーネントは関数コンポーネントで書く
```

- 技術スタックを明示する（毎回説明しなくて済む）

## Claude Codeへの指示の出し方：コツと実例

指示の出し方には慣れが必要です。

最初は「ログイン機能を作って」と雑に投げていました。これだと返ってくるコードが、自分のプロジェクトに合っていないことが多かったです。

指示のテンプレートはこれです。

```
【やりたいこと】
〇〇という機能を追加したい。

【現状】
現在、△△というファイルに◻◻という処理が書いてある。

【期待する動き】
ボタンをクリックすると、□□が表示される。

【制約・注意点】
既存の□□の処理は変えないでほしい。
```

具体的な例を出します。

**Before（ダメな指示）**
```
Stripeの決済機能を追加して
```

**After（良い指示）**
```
【やりたいこと】
月額480円のサブスクリプション機能を追加したい。

【現状】
src/lib/stripe.tsにStripeの初期化コードがある。
ユーザー情報はSupabaseのusersテーブルに保存している。

【期待する動き】
「プレミアムにアップグレード」ボタンを押すと
Stripeの決済ページに遷移する。
決済完了後、usersテーブルのis_premiumをtrueに更新する。

【制約】
既存のAuthの処理は変えないでほしい。
```

この粒度で指示を出すと、1回で使えるコードが返ってくる確率が上がりました。

## 詰まった10個のポイントと解決策

### 1. 環境構築：Node.jsのバージョン問題

**症状**
npm install を実行するとエラーが出る。

**原因**
Node.jsのバージョンが古かった。必要なバージョンは18以上だった。

**解決策**
nvmを使ってNode.jsのバージョンを切り替える。

```bash
# nvmのインストール（Mac）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash

# Node.js 18のインストール
nvm install 18
nvm use 18
```

---

### 2. Supabaseの環境変数が読み込まれない

**症状**
ローカルでは動くのに、Vercelにデプロイするとログインできない。

**原因**
.envファイルに書いた環境変数がVercelに設定されていなかった。

**解決策**
Vercelのダッシュボードから「Settings → Environment Variables」に進む。
.envファイルに書いた変数を手動で追加する。

必要な変数はこの2つ。
```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJxxx...
```

Vercelへのデプロイ時は、.envを設定するだけでは足りません。これを知らずに2時間溶かしました。

---

### 3. Reactのhydrationエラー

**症状**
ブラウザのコンソールに「Hydration failed because the initial UI does not match」と出る。

**原因**
ログイン状態によって表示を切り替える処理が、サーバーサイドとクライアントサイドで一致していなかった。

**解決策**
Claude Codeに症状をそのまま伝えて、エラーメッセージを貼り付けたら解決コードを出してくれました。

```
このエラーが出ています。
「Hydration failed because the initial UI does not match what was rendered on the server」
ログイン状態によってヘッダーの表示を切り替えているコンポーネントです。
修正してください。

（エラーが出ているコンポーネントのコードを貼り付ける）
```

エラーメッセージはそのまま貼る。これが一番効きます。

---

### 4. Stripeのwebhookが動かない

**症状**
Stripeで決済が完了しても、アプリ側のDBが更新されない。

**原因**
Stripeからのwebhookを受け取るエンドポイントが設定できていなかった。

**解決策**
Stripeのダッシュボードから「開発者 → Webhooks → エンドポイントを追加」を選ぶ。

エンドポイントのURLは
```
https://あなたのドメイン.vercel.app/api/webhook
```

受け取るイベントは
```
checkout.session.completed
customer.subscription.deleted
```

この2つを選べば最低限の動作はします。

---

### 5. PDF出力でフォントが文字化けする

**症状**
請求書をPDFに出力すると日本語が□□□になる。

**原因**
使っていたPDFライブラリ（jsPDF）がデフォルトで日本語フォントを持っていない。

**解決策**
react-pdf/rendererというライブラリに乗り換えました。

Claude Codeに「jsPDFで日本語が文字化けする。別の方法を教えて」と伝えたら、react-pdf/rendererを提案してくれました。フォントファイルを自分でプロジェクトに追加する必要がありますが、手順も教えてくれました。

---

### 6. TypeScriptの型エラーが大量に出る

**症状**
書いてもらったコードを貼り付けると、型エラーが100個出る。

**原因**
Supabaseが自動生成する型定義ファイルを作っていなかった。

**解決策**
Supabase CLIで型定義ファイルを生成する。

```bash
npx supabase gen types typescript --project-id あなたのプロジェクトID > src/lib/database.types.ts
```

このファイルを作ると、DBのテーブル構造をTypeScriptが理解してくれます。型エラーが激減します。

---

### 7. ローカルでは動くのに本番で動かない（CORS問題）

**症状**
Vercelにデプロイしたら、APIへのリクエストが全部エラーになる。

**原因**
SupabaseのCORSの許可ドメインにVercelのURLが追加されていなかった。

**解決策**
Supabaseのダッシュボードから「Authentication → URL Configuration」を開く。

「Redirect URLs」に以下を追加する。
```
https://あなたのドメイン.vercel.app/**
```

---

### 8. GitHubへのpushが怖くて手が止まる

**症状**
GitHubを使ったことがなく、コマンドを打つのが怖い。

**解決策**
これはツールの問題ではなく、気持ちの問題でした。

最初はGitHub Desktopというアプリを使いました。GUIで操作できるので、コマンドなしでGitHubに上げられます。

慣れてきたらターミナルに移行しました。基本的に使うコマンドはこの4つだけです。

```bash
git add .
git commit -m "変更内容のメモ"
git push origin main
```

---

### 9. Claude Codeが同じエラーを直せない

**症状**
エラーを投げてもClaudeが修正コードを出してくれるが、動かない。それを投げるとまた別のコードが来る。無限ループ。

**原因**
Claude Codeの文脈が長くなりすぎて、プロジェクトの全体像を見失っていた。

**解決策**
一度会話をリセットして、新しいセッションで「新しいことを試す」姿勢で取り組む。

リセット前に、問題を整理します。

```
問題：□□のエラーが出る
試したこと：○○と△△を試したが、どちらもダメだった
現在のコード：（コードを貼る）
エラーメッセージ：（エラーを貼る）
```

これで新しいセッションを始めると、解決策が変わることがあります。

## リリースまでの手順（Vercel + Stripe）

### Vercelへのデプロイ

1. GitHubのリポジトリにコードをpushする
2. vercel.comでアカウントを作る
3. 「New Project」からGitHubのリポジトリを選ぶ
4. 環境変数を設定する（前述）
5. 「Deploy」を押す

これだけです。5分かかりません。GitHubにpushするたびに自動でデプロイされます。

### Stripeで月額プランを設定する

1. stripe.comでアカウントを作る
2. 「製品 → 製品を追加」から月額プランを作る
3. 価格を設定する（今回は480円/月）
4. 「本番環境のAPIキー」をコピーして環境変数に設定する
5. webhookの設定をする（前述のポイント4を参照）

Stripeは最初「本番環境」ではなく「テスト環境」でテストできます。テスト用のカード番号は`4242 4242 4242 4242`です。これで実際に決済フローを確認できます。

## 非エンジニアが最初にやるべき3つのこと

4ヶ月やってみて、最初に戻れるならこの順番でやります。

**1. 環境構築に2〜3日かけることを覚悟する**

「なぜ動かないのか」がわからない時期が必ずあります。これは普通です。Node.jsのバージョン、パスの設定、npmのキャッシュ…。環境構築でつまずいても、アプリ開発の才能がないわけではありません。全員が通る道です。

**2. CLAUDE.mdを最初に書く**

プロジェクトを始める前に、5〜10分でCLAUDE.mdを書いてください。「何を作るか」「何を使うか」「どんなルールで書くか」を書くだけです。これがあるかないかで、開発の速さが変わります。

**3. エラーはそのままコピペする**

「TypeError: Cannot read properties of undefined」というエラーが出たら、それをそのままClaude Codeに貼り付けてください。日本語に訳したり、要約したりしなくていいです。エラーメッセージには原因のヒントが含まれています。そのままClaudeに渡すのが一番効率的です。
