# Kindle出版をClaudeで効率化したら出版サイクルが3倍速くなった

---

Kindle出版を始めて3年。最初の1冊を出すのに2ヶ月かかった。
でも今は、企画から出版まで3週間もあれば終わる。
何が変わったかというと、Claude（Anthropic製のAI）をワークフローに組み込んだことだった。

「AIで本が書ける」という話は前から耳にしていた。でも正直、最初は懐疑的だった。「それって本当に自分の本になるの？」という疑問があったから。

今回は、その疑問がどう変わったか、実際にどう使っているか、正直に書いていきます。

---

## 自己紹介と副業の背景

沖縄在住、会社員の佐伯亮です。

本業は普通のオフィスワーク。副業としてKindle出版、Webアプリ開発、note販売をやっています。Kindleはこれまで8冊出版済み。

Kindle出版を始めたのは「ストック収益が欲しかった」という動機から。毎月労働時間を増やさずに収入を増やすには、一度作ったものが売れ続ける仕組みが必要だと思ったんです。

でも現実はきつかった。

1冊書くのに、休日をほぼ全部使っていた。本業が終わって帰ってきてから深夜まで書く、みたいな生活。それで出版サイクルが落ちて、収益も頭打ちになっていった。

「もっとペースを上げたいけど、時間がない」という状態がずっと続いていました。

---

## Claudeを使い始めたきっかけ

転機は去年の秋でした。

8冊目の出版が終わった後、「次は何を書こう」と思いながら何も動けない期間が1ヶ月続いた。書きたいテーマはあるのに、構成が固まらない。書き出しが決まらない。

そのとき、Claudeにアウトラインを相談してみたんです。

正確には「相談」というより「壁打ち」に近かった。「こういうターゲットに向けてこういうテーマで書きたいんだけど、どういう章立てが良いと思う？」と入力してみた。

返ってきた内容が、思ったより使えた。

完璧ではない。でも「自分が考えていたこと＋自分が見落としていた視点」が整理されていて、そこから修正するのが思ったより速かった。

「これは使えるかもしれない」と思って、ちゃんと実験してみることにしました。

---

## AI副業の現実：甘くない部分を正直に

最初に言っておきます。

**Claudeを使えば誰でも簡単に本が書けるわけではない。**

これは声を大にして言いたい。

実際に使ってみてわかったのは、Claudeは「書く補助」であって「書いてくれるもの」ではないということ。

何も考えずに「Kindle本を書いて」と頼んでも、返ってくるのは薄い情報をそれっぽく並べただけの文章。読んだらすぐわかる。深みがない。自分の実体験も入っていない。

そういう本は売れない。というか、読んでいてつまらない。

じゃあ何が必要かというと、**自分の軸をちゃんと持って使うこと**。

- どんな読者に向けて
- どんな実体験を元に
- 何を伝えたいか

この3つが自分の中で固まっていないと、Claudeをどれだけ使っても出てくるのは「それっぽい文章」にしかならない。

私自身、最初の2〜3回は失敗した。AIに頼りすぎた章があって、後で読み直したら「これ、自分が書いたんじゃないな」という感じがして、全部書き直した。それで時間を余計に使った。

**AIを使う前提として、自分の一次情報があること。** これが絶対条件だと今は思っています。

その前提の上で使うと、話が変わる。

## どこで効率が変わったか

Claudeをワークフローに入れてから、出版サイクルが変わった箇所は大きく3つ。

**① 構成作りにかかる時間**

以前：1〜2週間（ぼんやり考えながら固まっていく感じ）
今：2〜3日（壁打ちしながら修正していく）

以前は「構成を考えている」というより「なんとなく考えている状態が続いている」感じだった。Claudeと対話形式で進めると、強制的にアウトプットが出るから、詰まったままにならない。

**② 各章の下書き**

以前：1章あたり2〜3時間
今：45分〜1時間

下書きの粗いドラフトをClaudeに出してもらって、自分の実体験や具体例を肉付けしていく。ゼロから書くより「修正・加筆」の方が速い。これは本当にそうで、白紙に向かうより埋まっているものを直す方がずっと動きやすい。

**③ タイトルとキャッチコピー案**

以前：悩みながら1日
今：30分

タイトルは売れ行きに直結するから一番悩む部分だった。でも自分一人で考えると視野が狭くなる。Claudeに「このターゲット・このテーマ・このポジションでタイトル案を20個出して」と頼んで、そこから選んで磨く方が圧倒的に速い。

---

## 実際に使っているプロンプトの構造

抽象的な話は終わりにして、具体的に書きます。

私がClaudeに使っているプロンプトは、大きく3種類に分かれます。

**① 構成作りプロンプト**

```
【ターゲット】
30代会社員で副業を始めたい人。
まだ何も始めていない初心者。
仕事が忙しくて時間が取りにくい。

【テーマ】
Kindle出版の始め方

【私の立場】
会社員として副業でKindle出版8冊経験。月収は安定して3〜5万円。

【依頼】
このターゲットに向けた7章構成のKindle本のアウトラインを作ってください。
各章に「その章で読者が得るもの」を一文で付けてください。
```

ポイントは「私の立場」を明示すること。

ここを抜くと、Claudeが一般的な情報を並べてしまう。「私はこういう人間で、こういう経験がある」という前提を渡すと、それに合わせた構成が返ってくる。

**② 章の下書きプロンプト**

```
【書く章】
第3章：Kindleで「売れるテーマ」の選び方

【この章で伝えたいこと】
需要のある市場を選ぶことが先で、書きたいことを書くのは後回し。

【私の実体験】
最初に書いた本は自分が好きなテーマで書いて全然売れなかった。
2冊目からリサーチ先行に切り替えて月3万円を超えた。

【文字数】
約3000字

【依頼】
この章の下書きを書いてください。
私の実体験を核にしてください。
読者への問いかけを適宜入れてください。
```

これで返ってきた下書きは、そのままでは使えない。でも「骨格」はできている状態。そこに自分の言葉、具体的なエピソード、感情の揺れを書き足していく。

作業時間は、ゼロから書くより4割くらい速い感覚があります。

**③ タイトル・キャッチコピープロンプト**

```
【本の内容】
副業初心者の会社員がKindle出版で月3万円稼ぐまでの手順書。
AIを使って効率化する方法も含む。

【ターゲット】
副業でKindle出版を考えている30〜40代会社員。

【避けたいトーン】
・「稼げる」系の煽り
・詐欺っぽい感じ
・玄人向けすぎる表現

【依頼】
Kindleのタイトルと副題の組み合わせを15案出してください。
】
```

15案出してもらって、自分でさらに変形させる。この「変形の元になるものがある状態」がとにかく速い。

## 失敗した3つのパターン

ここが今回の記事で一番書きたかった部分です。

**失敗① AIに全部投げようとした**

8冊目が終わった後、「次こそAIにほとんど書かせてみよう」と思って実験した本がある。

結果：書き上がったものの、出版前に自分で読み直して全部ボツにした。

読んでいて、自分の声がしなかった。情報は正確かもしれないけど、「なぜこれを書いているのか」という熱量がゼロ。Kindleは安い値段でも買ってもらうのに「この人から学びたい」という感覚が大事だと思っていて、それが完全に消えていた。

結局、AIの出力を参考にしながら全部書き直した。時間を二重に使うことになった。

**教訓：AIは「自分の思考を速く形にするツール」で、「代わりに考えてくれるもの」ではない。**

**失敗② プロンプトが雑だった時期**

最初のうちは「〇〇について書いて」くらいのプロンプトで使っていた。

返ってくるのはそれなりに見える文章。でも使おうとすると全然使えない。ターゲットも自分の立場も伝えていないから、誰向けなのかよくわからないものが出てくる。

これで「Claudeって大したことないな」と感じていた時期があった。

プロンプトの質を上げてから、一気に使えるようになった。「AIの質はプロンプトの質で決まる」というのは本当だった。

具体的には、プロンプトに必ず「ターゲット」「自分の立場・実績」「避けてほしいこと」の3つを含めるようにしてから、出力の質が上がりました。

**失敗③ Claudeへの依存でリサーチを怠った**

構成が速く作れるようになったせいで、「市場リサーチ」を飛ばすことがあった。

Claudeに構成を作ってもらった本が、実は「Kindleで需要が薄いジャンル」だったことが後からわかった。

売れなかった。

当然です。どんなに効率よく作っても、需要がなければ意味がない。

AIを使っても、**Amazonで売れ筋を確認する・競合作品を読む・レビューから読者の不満を拾う**、この基本リサーチは省略できない。むしろ、効率が上がった分、リサーチに時間をかけられるようになった、と考えた方がいい。

## 月収の推移と出版冊数の関係

正直な数字を書きます。

| 期間 | 累計出版冊数 | Kindle月収（平均） |
|------|------------|------------------|
| 〜2冊目 | 2冊 | 3,000〜5,000円 |
| 〜4冊目 | 4冊 | 8,000〜12,000円 |
| 〜6冊目 | 6冊 | 18,000〜25,000円 |
| 〜8冊目（Claude導入後） | 8冊 | 35,000〜50,000円 |

Claudeを導入したのは7冊目の途中から。8冊目から本格的に活用している。

出版ペースが上がったことで、冊数が増えた。冊数が増えると、それぞれの本が少しずつ売れるストック収益の積み上げが効いてくる。

1冊あたりの売上が「少し上がった」のではなく、**本数が増えたことで合計が増えた**、というのが正確な表現です。

誤解してほしくないのは、「Claudeを使ったから売れるようになった」ではないこと。

**出版ペースが上がった → 試行錯誤が速くなった → 何が売れるかの感覚が磨かれた → 結果として収益が上がった**

という連鎖です。

## 再現性のある仕組みの作り方

私が今使っているKindle出版のワークフローをそのまま書きます。

**ステップ1：リサーチ（3〜4日）**

- Amazonのジャンル別売れ筋を確認
- 競合本のレビューを20件以上読む
- 「不満」「欲しかった情報」をメモする
- 自分が実体験で語れる範囲か確認する

ここはClaudeはほぼ使わない。人間がやる部分。

**ステップ2：構成作り（2〜3日）**

- Claudeと壁打ちしてアウトラインを作る
- 自分で修正・調整する
- 各章で「自分の実体験を使える部分」を洗い出す

**ステップ3：執筆（1〜1.5週間）**

- 各章の下書きをClaudeに出してもらう
- 自分の実体験・具体例・感情を書き加える
- 一度寝かせて翌日に読み直す
- 「AIっぽい文章」を自分の言葉に直す

**ステップ4：タイトル・表紙・出版（3〜4日）**

- タイトル案をClaudeで複数出す
- 自分で選んで磨く
- 表紙はCanva（テンプレートをアレンジ）
- Kindle ダイレクト・パブリッシングで出版手続き

合計で3週間以内。以前は6〜8週間かかっていたので、ほぼ倍速以上です。

## 初月から動けるロードマップ

「やってみたいけど何から始めれば」という人のために、最小限の手順を書きます。

**Week 1：リサーチと企画**
- Kindleのジャンルを1つ決める
- そのジャンルの売れ筋上位20冊のタイトルとレビューを読む
- 自分の実体験で書けるテーマを1つ決める

**Week 2：Claudeで構成を作る**
- 上記の構成プロンプト（この記事に書いたもの）を使う
- アウトラインを作って、自分で修正する
- 各章の「言いたいこと」を箇条書きにまとめる

**Week 3〜4：執筆**
- 1日1章を目標にする
- Claudeの下書き→自分で加筆修正
- 完璧を目指さない。8割の完成度で出す方が速い。

**Week 4後半：出版準備**
- タイトルをClaudeで複数案出す
- Canvaで表紙を作る（1〜2時間）
- KDPで出版手続き

最初の1冊で完璧を求めると動けなくなる。1冊目は「やり方を覚える本」と思って出してしまう方が、長期的には正解です。

## まとめ

Claudeを使って変わったのは、出版スピードだけじゃなかった。

「構成に詰まって止まる」という状態が減った。壁打ち相手がいるだけで、頭が動きやすくなった。

ただ、繰り返しになりますが、**自分の実体験や考えがない状態でAIを使っても、薄いものしかできない**。

Claudeはあくまで「自分の思考を整理して速くアウトプットするツール」。核になるのは、自分の経験と、読者への誠実さだと思っています。

副業としてKindle出版を考えている人に伝えたいのは、「AIを使えば楽になる」ではなく「AIを使えば試行錯誤のスピードが上がる」ということ。

速くなった分、もっと多く試せる。多く試した分、早く掴めるものがある。

それが今の私の認識です。
