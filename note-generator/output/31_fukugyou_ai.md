# ClaudeでKindle本の構成を作ったら執筆時間が半分になった

---

Kindle本を書くとき、一番しんどいのは「書くこと」じゃないと思っています。

一番しんどいのは、**何をどの順番で書くか決めること**です。

ここで詰まって、「構成考えてたら週末が終わった」みたいな経験、ある人は多いんじゃないでしょうか。僕は何度もやりました。

---

## 自己紹介と、Kindle副業の現実

沖縄在住の会社員、佐伯亮です。

副業でKindle出版をやっていて、これまでに8冊出しています。本業は別にあって、夜と週末の時間を使って書いています。

Kindle出版を始めたのは3年ほど前。「ストック収益がほしい」という、シンプルな動機でした。

正直にいうと、最初の2〜3冊は本当に時間がかかりました。1冊書くのに平均で**30〜40時間**かかっていたと思います。週末2〜3回分を全部つぎ込む感じ。それで出来上がるのが1万5,000〜2万字の本。

「こんなペースじゃ続かない」と何度か思いました。

本業が忙しい時期は、構成だけ考えて何週間も止まる、ということもありました。

---

## AIを使い始めたきっかけ

ChatGPTが話題になり始めた頃から、ライティング補助として使い始めました。

でも最初は「下書きを書かせる」という使い方をしていて、正直いまいちでした。

AIが書いた文章ってわかるんですよね。どこかのブログを要約したみたいな文体で、自分の言葉じゃない。そのままじゃ出せないので、結局ほぼ全部書き直す。手間が減らない。

そこで「書かせる」をやめて、「構成を考えさせる」に切り替えたんです。

きっかけは小さなことで、ある夜、章立てで悩んでいたときにClaudeに投げてみたんです。「こういうテーマのKindle本を書きたい、読者はこういう人、こういうことを伝えたい」と。

返ってきた構成を見たとき、**「あ、これ自分が3時間考えても出なかった」**と思いました。

---

## Claudeが構成を作ると何が変わるか

ここが本題です。

具体的に何がどう変わったか、数字と一緒に書きます。

### Before（Claudeなし）

- 構成を考える時間：**3〜5時間**
- 各章の小見出しを決める時間：**1〜2時間**
- トータル執筆時間：**30〜40時間**

### After（Claudeで構成）

- 構成をClaudeに叩き台を作ってもらう：**20〜30分**
- 自分でブラッシュアップする時間：**1時間程度**
- トータル執筆時間：**15〜20時間**

半分以下になりました。驚いたのは「構成が決まれば書くのが早い」という当たり前のことを、身をもって実感したことです。

構成が曖昧なまま書き始めると、途中で「この章、いる？」「第3章と第5章、内容かぶってない？」という迷いが出る。それが執筆の中断を生む。

Claudeが叩き台を作ってくれると、**迷いの量が激減する**んです。

## 実際にどんなプロンプトを使ったか（一部公開）

詳しい手順は有料パートに書きますが、基本の考え方だけ先に共有します。

Claudeへの投げ方で大事なのは、**3つの情報を最初に渡すこと**です。

1. **誰に向けて書くか**（読者像を具体的に）
2. **その読者の悩みや状況**
3. **本を読んだ後に読者に何ができてほしいか**

この3つを揃えると、Claudeが返してくる構成の精度がまったく違います。

「〇〇についてのKindle本の構成を作って」だけだと、汎用的な目次が返ってきます。でも3つ揃えると、**その読者に刺さる順番と切り口**が出てくる。

これ、最初に気づいたときは本当に「なるほど」と声が出ました。

## 「AI副業は簡単」の半分嘘について

正直に書いておきます。

ClaudeでKindle本の構成を作れるようになった今も、**うまくいかないことはあります**。

たとえば、ニッチすぎるテーマはClaudeが苦手なことがある。「沖縄の中小企業向けのDX推進」みたいな、領域が狭くて地域性が強いテーマだと、出てくる構成が一般論になりがちです。

あと、Claudeが出した構成をそのまま採用すると、「整いすぎた本」になるリスクがある。章の流れが教科書的すぎて、読んでいて飽きる感じ。

だから僕は、Claudeの構成を**「第1案」**として使って、必ず自分で手を入れます。「この章順、読者が途中で離脱しそう」とか「ここは体験談を先に持ってきたい」とか。

AIが叩き台を作り、人間が判断する。この役割分担が一番うまく機能しています。

| 2冊目 | 3年前 | 副業入門 | 35時間 | なし |

### 実際に使っているプロンプト（全文）

これが核心です。

8冊を通して精度を上げてきた、構成作りのプロンプトを全文公開します。

```
あなたはKindle出版の編集者です。
以下の条件でKindle本の章構成を作ってください。

【本の基本情報】
- テーマ：[ここにテーマを入れる]
- 想定文字数：[1万5,000〜2万字 など]
- 価格：[99円 / 499円 など]

【読者情報】
- 読者像：[できるだけ具体的に。職業・年齢・状況など]
- 読者の現在地：[今その人が抱えている悩みや状況]
- 本を読んだ後の状態：[読後に読者が何を理解し、何ができるようになってほしいか]

【著者のスタンス】
- 著者の立場：[初心者目線 / 実践者として / など]
- 盛り込みたい実体験：[自分が経験したこと、数字など]
- 避けたいトーン：[上から目線 / 難しい専門用語 / など]

【アウトプット形式】
- 章数：5〜7章
- 各章に「小見出し案（3〜4個）」と「章の役割（何を達成するための章か）」を追記してください
- 最後に「この構成の意図」を200字以内で説明してください
```

このプロンプトのポイントは**「章の役割」を明示させること**です。

ただの目次じゃなく、「なぜこの順番か」の意図が出てくる。それがあると、自分でブラッシュアップするときに「この章、役割かぶってるな」と気づけます。

### 実際にこのプロンプトを使って出てきた構成例

7冊目「沖縄×リモートワーク」のときの投げ方と、返ってきた構成を一部公開します。

**投げた内容（抜粋）**

```
読者像：都市部勤務の会社員（30代・子持ち）で、沖縄移住に興味はあるが
「仕事はどうする？」「生活費は？」が不安で踏み出せない人

読者の現在地：移住系SNSを見て憧れているが、具体的な情報が少なく
「結局どうすればいいかわからない」状態

本を読んだ後の状態：「沖縄でリモートワークをするための現実的なステップ」が
理解でき、自分の状況に当てはめて考えられる
```

**Claudeが返してきた構成（要約）**

```
第1章：「移住したいけど踏み出せない」の正体
→ 役割：読者の不安を言語化し、共感をつくる

第2章：沖縄のリアルな生活コストと収入の目安
→ 役割：数字で不安を具体化し、「考えられる問題」に変換する

第3章：リモートワークで沖縄に住むための3つの条件
→ 役割：行動可能な条件を示す

第4章：移住前に必ずやること・やらなくていいこと
→ 役割：行動の優先順位をつける

第5章：移住後の現実（うまくいったことと失敗したこと）
→ 役割：著者体験談で読者の「自分もできそう」を引き出す

第6章：沖縄リモートワーク生活の始め方・ステップガイド
→ 役割：具体的なアクションに落とす
```

この構成、自分では「第1章を共感で始める」という発想が出てきませんでした。

どうしてもノウハウから始めたくなる。でもClaudeは「読者の不安を言語化する章」を最初に入れてきた。読んだとき「たしかにそっちが先だ」と思いました。

### 構成を受け取った後の「ブラッシュアップ手順」

Claudeの構成をそのまま使わない理由は、さっき書いた通り「整いすぎる」から。

僕は必ず以下の手順でブラッシュアップします。

**ステップ1：「読者の心理変化」を追ってみる**

章を順番に読んで、「この読者の気持ちはどう変化するか」を考えます。「不安→共感→理解→行動意欲」みたいな流れが自然かどうか。

**ステップ2：「この章、なくていい？」と一章ずつ問う**

6章あったら6回聞きます。「この章が抜けたら読者は困るか？」。困らないなら削るか統合します。

**ステップ3：自分の実体験が入る場所を決める**

どの章に「自分が経験した話」を入れるか、先にマーキングします。体験談がない章は「本当に自分が書くべきか」を考えます。

**ステップ4：小見出しを自分の言葉に直す**

Claudeの小見出しはきれいすぎることが多い。「〇〇の方法」じゃなくて「〇〇したとき、正直こう思った」みたいな、自分の語り口に変えます。

この4ステップで1時間かかります。でもこれをやると、Claudeの構成が「自分の本」になる感じがします。

---

### 執筆中にClaudeを使う場面（構成以外）

構成だけじゃなく、執筆中にも2つの場面でClaudeを使っています。

**場面1：章の導入文を考えるとき**

章の最初の段落は一番難しい。「この章で何を書くか」はわかっていても、「どう書き出すか」で詰まります。

このとき「この章の内容は〇〇。読者は△△な状態。どんな書き出しが効果的ですか？3パターン出してください」とClaudeに聞きます。

3パターン出してもらって、そのどれも使わないことも多い。でも「こういう切り口があるか」という気づきで、自分の書き出しが決まることがよくあります。

**場面2：「この説明、わかりにくくない？」のチェック**

自分が書いた段落を貼って「この説明、IT知識がない30代の会社員に伝わりますか？わかりにくい部分を指摘してください」と聞きます。

指摘された箇所を直すと、読者目線の文章になる。自分では気づけない「わかったつもり」の説明が炙り出されます。

### 月収の変化と、時間効率の正直な話

Kindle副業の収益は、出せば出すほど少しずつ上がっています。

ただ、「急に増えた」という経験はしていません。

僕の場合、8冊で月平均3〜4万円のロイヤリティ収入が定常化しています。本によってバラツキがあって、月1,000円台の本もあれば、月8,000円超える本もある。

時間効率でいうと、1冊あたりの執筆時間が38時間→14時間になったので、同じ時間で2〜3冊出せるようになりました。

収益が「2〜3倍になった」と言いたいところですが、テーマ選びや表紙・タイトルの影響も大きいので、単純に「時間を減らした分だけ収益が増えた」ではありません。

正直なところを言うと、**「書ける本の数が増えた」という変化が一番大きい**。

月2〜3万円が月3〜4万円になったのは、Claudeのおかげだけじゃなく、本数を増やせたからです。

### 初月から動けるロードマップ

最後に、「Claudeを使ったKindle執筆」を始める人向けのロードマップを書きます。

**Week 1：テーマと読者を決める**

Claudeを使う前に、「誰に何を伝えるか」を言語化します。ここが曖昧だとClaudeの構成精度が下がります。

A4用紙1枚に「読者像・読者の悩み・本を読んだ後の状態」を書き出す。それだけでいいです。

**Week 2：構成プロンプトを投げ、ブラッシュアップする**

上で公開したプロンプトを使って構成をもらいます。4ステップでブラッシュアップして、章ごとのボリューム感（何文字書くか）を決めます。

**Week 3〜4：本文を書く**

構成が決まれば、あとは各章を順番に埋めるだけです。詰まったら章の導入をClaudeに聞きます。

1章あたり2,000〜3,000字を目安にすると、5〜6章で1万5,000字前後になります。

**Month 2：出版・様子を見る**

KDPで出版して、最初の1〜2週間は広告なしで様子を見ます。

検索流入がどこから来ているかをKDPのレポートで確認して、タイトル・サブタイトルを調整します。

### まとめ：「半分になった」の意味

Claudeを使って執筆時間が半分になった。

これは「楽になった」という話じゃなく、**「迷う時間が減った」**という話です。

何を書くか、どの順番で書くか。この迷いが執筆時間の半分以上を占めていた。Claudeがそこを高速で叩き台にしてくれるから、自分は「判断する」ことに集中できる。

副業でKindleを書く人の多くは、時間が足りません。本業がある中でつくっている。

だからこそ、「迷う時間を減らす」ことが一番効く。Claudeはそこに使うのが正解だと、8冊やって確信しています。
