# Claude Codeを1ヶ月使ってわかった本当の使い方

---

## コードが書けなくても、アプリは作れる。これは本当の話です。

「Claude Codeって難しそう」と思ってた自分が、1ヶ月後にはWebアプリをリリースしてた。

そういう話をします。

ただし、「簡単です！誰でもできます！」みたいな話じゃないです。つまずいたし、迷ったし、「これ自分には無理かも」って思った瞬間も正直あった。

でも、乗り越え方がわかってきた。その話を書きます。

---

## 自己紹介：エンジニアじゃないけどアプリを作ってます

名前は佐伯亮です。沖縄在住の会社員で、副業でAI活用とアプリ開発をやってます。

プログラミングは独学で少しかじった程度。Python、JavaScript、React……名前は知ってるし、コードを読んでなんとなく意味はわかるけど、「ゼロから書ける」かというと正直難しいレベルです。

Claude Codeを使い始める前、僕がアプリを作る手段といえばChatGPTにコードを生成させてコピペ、でした。それでもWebアプリを2本リリースできてはいた。でも毎回「これで合ってるのか？」という不安と戦いながら、1機能追加するのに3〜4時間かかってた。

Claude Codeを知ったのはXのタイムライン。「ターミナルで動くAIコーディングエージェント」というのを見て、「何それ面白そう」と思ったのが始まりでした。

---

## Claude Codeとは何か、一言で言うと

普通のAIチャット（ChatGPT、Claudeのブラウザ版など）との違いを一言で言うと——

**「AIが、あなたのパソコンの中で直接作業する」**

これに尽きます。

ブラウザのChatGPTにコードを出してもらう場合、自分でそのコードをファイルにペーストして、ターミナルで実行して、エラーが出たらまたAIに相談して……というサイクルを繰り返す必要があります。

Claude Codeは違う。ターミナル上でClaude Codeを起動すると、AIがファイルを直接読んで、書き換えて、コマンドも実行してくれます。

「loginページ作って」と指示したら、勝手にファイルを作って、コードを書いて、「完了しました」と報告してくる。

最初に見たとき「これ、魔法じゃないか」と思いました。

ただ、1ヶ月使ってみてわかったのは、「指示の仕方」と「どこまで任せるか」を間違えると、思ったように動かないということ。

魔法ではなく、道具です。道具の使い方を覚える必要がある。

---

## 1ヶ月で見えてきた「本当の使い方」の輪郭

Claude Codeを始めた最初の1週間は、ほぼ失敗の連続でした。

「タスク管理アプリを作って」とだけ打ち込んだら、確かに動くものはできた。でも思ってたのとぜんぜん違う。UIがシンプルすぎて、データの保存もされない。

「なぜ自分の思った通りにならないんだろう」と悩んで気づいたのは、指示が抽象的すぎたことでした。

人間に仕事を頼むときも同じですよね。「いい感じにやっておいて」は失敗する。「Aという条件でBをCまでにやってほしい」が正しい頼み方。

Claude Codeへの指示も全く同じ原則が通用することがわかってきました。

1ヶ月間で書いたメモを見返したら、「これが効いた」と思ったポイントが3つに絞れました。

**①最初に「完成形の定義」を言語化してから始める**
**②「一気にやって」ではなく、機能ごとに分けて指示する**
**③エラーが出たとき、自分で直そうとしない**

この3つについて、有料パートで実際の指示文・スクリーンショット・具体的なやりとりを見せながら解説します。

## 「もう無理かも」と思ったときの話

1ヶ月の中で一番しんどかったのは、3週目でした。

ユーザー認証機能（ログイン・ログアウト）を実装しようとしていて、SupabaseとClaudeを連携させるところでエラーが止まらなくなった。

Claude Codeに「直して」と頼んで、直してもらって、また別のエラーが出て、また頼んで……これが2時間続いた。

「なんで自分はエンジニアじゃないのに、こんな沼にはまってるんだろう」と、正直思いました。

結局、問題の原因は「Supabaseの設定画面でURLのコピーをミスっていた」という超初歩的なことだった。AIの問題じゃなく、自分の環境設定のミスだった。

でも、これで大事なことを学びました。

**エラーが続くときは、AIを疑う前に「自分の環境を疑え」**

SupabaseのダッシュボードURL、環境変数（.envファイル）の設定、VercelへのデプロイのときのAPIキー……この辺の設定ミスが、Claude Codeをうまく使えない原因の70%くらいを占めてます。少なくとも自分の場合は。

## 実際に作ったもの：AIメモアプリの全記録

1ヶ月の間に完成させたのは、「AIが内容を要約してタグ付けしてくれるメモアプリ」です。

構成はこうです。

- フロントエンド：Next.js（React）
- バックエンド・DB：Supabase
- AI機能：Claude API（claude-3-5-sonnetを使用）
- デプロイ：Vercel

エンジニアの方からすると「普通の構成ですね」と言われそうですが、1ヶ月前の自分はこの構成を「自力でゼロから組む」なんて絶対無理だと思ってた。

完成まで約16時間（作業ログを記録してました）。うち4時間はエラー対応と環境設定。

コードをゼロから書いた部分は、ほぼゼロです。

## 有料パート：Claude Codeの本当の使い方、全部書きます

### まず「CLAUDE.md」を作ることが最初の一手

Claude Codeを使うとき、多くの人が最初にやらないこと——それがCLAUDE.mdの設定です。

CLAUDE.mdとは、プロジェクトのルートディレクトリに置く「AIへの指示書ファイル」です。このファイルに書いた内容を、Claude Codeは作業を始める前に必ず読んでくれます。

自分がCLAUDE.mdに書いた内容を公開します。

```markdown
# プロジェクト概要
これはAIメモアプリです。ユーザーがメモを入力すると、
Claude APIが自動で要約とタグ付けを行います。

# 技術スタック
- Next.js 14（App Router使用）
- Supabase（認証・DB）
- Claude API（claude-3-5-sonnet）
- Vercel（デプロイ先）

# 開発ルール
- TypeScriptを使うこと
- コンポーネントは src/components/ に作成
- API Routeは src/app/api/ に作成
- 環境変数は .env.local に記載（.env.local は .gitignore 済み）
- コードに日本語コメントを入れること
- 変更を加えるときは必ず「何を変えたか」を教えること

# 現在のフォルダ構成
（ここにtreeコマンドの結果を貼る）
```

このファイルがあるとないとでは、Claude Codeの動き方が全然変わります。

CLAUDE.mdがない場合、AIは毎回「どんなプロジェクトかわからない」状態から始める。結果、的外れなコードを書くことが増える。

CLAUDE.mdがある場合、AIは文脈を持った状態で始められる。技術スタックも、フォルダ構成も、ルールも最初から把握した状態で作業してくれる。

**設定した翌日から、1回あたりの指示でうまくいく確率が体感で1.5倍くらい上がりました。**

### 実際に使った指示文（プロンプト）全公開

#### 【フェーズ1：プロジェクト立ち上げ】

最初の指示はこれでした。

```
まず最初に何も作らなくていいです。
以下の要件でアプリを作る場合、どんなファイル構成が適切か、
また最初に作るべき順番を教えてください。

要件：
- ユーザーがメモを書くと、Claude APIが要約とタグを自動生成する
- ログイン機能あり（Supabase Auth）
- メモの一覧表示、詳細表示、削除ができる
- デプロイはVercel予定
```

ポイントは**「いきなり作らせない」**こと。

最初に設計の確認をさせる。これをやるだけで、途中で「やっぱりフォルダ構成変えたい」という戻りが減ります。

Claude Codeが提案した構成に納得したら、「それで進めてください」と一言添えるだけ。

---

#### 【フェーズ2：機能ごとに分けた指示の実例】

ログイン機能を実装するときの指示はこうでした。

```
Supabase Authを使ったログイン機能を実装してください。

条件：
- メール・パスワードでのログインのみ（Googleログインは不要）
- ログイン後は /dashboard にリダイレクト
- 未ログイン状態で /dashboard にアクセスした場合は /login にリダイレクト
- ログアウトボタンはダッシュボードのヘッダーに設置

実装前に「何のファイルを作成・変更するか」の一覧を教えてください。
それを確認してからコードを書いてください。
```

最後の2行が大事です。

「実装前に変更ファイル一覧を教えて」という指示を入れると、AIが動く前に「これからやること」が見える。自分が意図しないファイルを触ろうとしていたら、ここで止められます。

実際、この確認をしなかったときに1度、Claude Codeがすでに完成していたコンポーネントを丸ごと書き換えてしまったことがありました。それ以来、「変更前に一覧を教えて」を必ず入れるようにしています。

---

#### 【フェーズ3：Claude API連携の指示】

AI機能（要約・タグ付け）を実装するときの指示です。

```
src/app/api/summarize/route.ts を作成してください。

このAPIは以下を行います：
1. POSTリクエストでメモの本文（text）を受け取る
2. Claude APIに「以下の文章を100文字以内で要約し、関連タグを3つ生成してください」とリクエスト
3. 要約文とタグの配列をJSONで返す

使用するモデル：claude-3-5-sonnet-20241022
環境変数名：ANTHROPIC_API_KEY（.env.localに設定済み）

エラー時は { error: "エラーメッセージ" } を返すようにしてください。
```

Claude APIを使うとき、モデル名と環境変数名を明示するのがポイントです。

これを書かないと、古いモデル名を使ってきたり、環境変数名を勝手に決めてきたりすることがあります。

### Supabase連携で詰まった3パターンと解決策

#### パターン①：環境変数のミス

症状：`Supabase client is not defined` というエラー

原因：.env.localに書いたSupabaseのURLやキーのコピーミス。URLの末尾にスペースが混入していた。

解決：.env.localファイルをテキストエディタで開き、値を目視確認。コピーするときはSupabaseダッシュボードの「Copy」ボタンを使う（手打ちは厳禁）。

#### パターン②：RLS（Row Level Security）の設定漏れ

症状：ログインしているのにデータが取得できない

原因：SupabaseのテーブルにRLSが有効になっているが、ポリシーを設定していなかった。

解決：SupabaseダッシュボードのAuthentication → Policiesで「ユーザーは自分のデータのみ読み書きできる」というポリシーを追加。

Claude Codeに「SupabaseのRLS設定でつまずいている。memosテーブルで、ログインユーザーが自分のメモだけ読み書きできるSQLを書いて」と頼んだら、そのままSupabaseのSQLエディタに貼れるコードを出してくれました。

#### パターン③：Supabaseのバケット未作成

症状：画像アップロードが404エラー

原因：Supabase StorageのバケットをClaude Codeが作ってくれると思っていたが、ダッシュボード側での手動作成が必要だった。

解決：SupabaseダッシュボードのStorage→バケット作成から手動で「images」バケットを作成。

**Claude Codeが「コードで作れないもの」と「ダッシュボードで手動設定が必要なもの」の区別を最初から知っておくと、詰まったときの対処が早くなります。**

---

### Vercelデプロイで失敗した3パターン

#### パターン①：環境変数の設定漏れ

ローカルでは動いているのに、Vercelにデプロイしたら動かない。

ほぼ確実に環境変数の設定が原因です。

VercelのダッシュボードでSettings → Environment Variablesを開いて、.env.localに書いた変数が全部登録されているか確認してください。

#### パターン②：ビルドエラー（TypeScriptの型エラー）

ローカルでは`npm run dev`で動いていても、Vercelのビルドは厳しい。型エラーがあると通りません。

解決策：デプロイ前に`npm run build`をローカルで実行する。これでVercelと同じビルドエラーが出ます。エラーが出たらClaude Codeに「このエラーを直して」と貼るだけ。

#### パターン③：Next.jsのApp RouterとPages Routerの混在

これは自分だけかもしれませんが、Claude Codeが途中からPages Router方式のコードを書いてきたことがありました。

CLAUDE.mdに「App Routerを使う」と明記しておくことで防げます。

### 非エンジニアが最初の1週間でやるべき5ステップ

ここが一番読んでほしい部分です。

1ヶ月の経験から、「最初の1週間でこれをやっておけばよかった」を5つにまとめました。

**Step 1：環境構築に1日かける（焦らない）**

Node.js、npm、Claude CodeのCLIインストール、VS Codeのセットアップ。ここは時間がかかって当然です。うまくいかない箇所はClaude Code（またはブラウザ版Claude）に聞きながら進める。

**Step 2：小さいものを1つ完成させる**

最初から「フル機能のアプリ」を作ろうとしない。「テキストを入力してボタンを押すと保存される」だけのシンプルなページを1つ完成させる。「完成させる体験」が重要。

**Step 3：CLAUDE.mdを最初に書く**

前述の通りです。プロジェクトを始めたらまずCLAUDE.mdを作る。後から追加してもいいけど、最初からある方が楽です。

**Step 4：「変更前に一覧を教えて」を習慣にする**

指示の最後に必ずこれを入れる。AIが思わぬファイルを書き換えることへの保険になります。

**Step 5：GitHubで変更を記録する**

Claude Codeが変更を加えるたびにgit commitする習慣をつける。何かおかしくなったときに戻れるので、精神的に楽になります。

Claude Codeに「今の変更をgitでコミットして」と頼めば、コマンドも実行してくれます。

### まとめ：Claude Codeは「任せる力」が問われる道具

1ヶ月使ってみての正直な感想は、「これはすごい道具だけど、使い手の指示力が試される」でした。

曖昧な指示をすれば曖昧な結果が返ってくる。具体的な指示をすれば、自分一人では到底作れなかったものが出来上がる。

コードの書き方を覚えるより先に、「やりたいことを言語化する力」を磨くことが非エンジニアにとって大事だと思っています。

それは、AIと話す力というより、自分が何を作りたいかを整理する力です。

Claude Codeはその力を持っている人に、本当によく応えてくれる道具でした。
