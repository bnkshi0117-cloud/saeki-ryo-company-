# Claudeで長文PDFを要約するプロンプトを試行錯誤した全記録

---

## 「とりあえず貼り付けるだけ」では限界があった

PDFをClaudeに読み込ませて要約させる。

やってる人は多いと思う。でも「なんか微妙な要約が返ってきて、結局自分で読み直した」という経験、ないですか？

僕はあります。それが何度も続いて、「プロンプトをちゃんと設計しないとダメだな」と気づいたのが、この試行錯誤の始まりでした。

---

## なぜPDF要約にClaudeを使うようになったか

仕事柄、行政の公示資料や業界のレポートを読む機会が多いです。沖縄の補助金系の資料とか、国が出す中小企業向けのガイドラインとか、平気で50〜100ページあります。

ChatGPTでも試したことはあるんですが、長文になるとトークンの上限に引っかかったり、「ファイルを添付しているのに文章として認識されてない」みたいなことがあって、扱いにくさを感じていました。

ClaudeはProプランだと**コンテキストウィンドウが最大200Kトークン**。PDFを丸ごと放り込んでも、けっこうな分量をそのまま処理してくれます。実際に試したところ、80ページ程度のPDFであれば1回のやり取りで問題なく読み込めました。

これはChatGPT（GPT-4o）との明確な違いで、「とにかく全文読ませたい」という用途ではClaudeの方が向いていると感じています。

ただ、読み込める＝使いやすい、ではないんですよね。最初はそこを勘違いしていました。

---

## 最初のプロンプトと、その失敗

最初に試したのはこんなプロンプトです。

```
このPDFを要約してください。
```

以上。シンプルすぎるのは分かってたんですが、「どんな要約が返ってくるか見てみたい」という気持ちで試しました。

返ってきたのは、構成をそのままなぞった要約でした。章ごとに2〜3行で説明される形式で、確かに正確ではあるんですけど、**「何が一番重要なのか」が全然わからない**。読んで、また元のPDFを読み直す羽目になりました。

要するに、「目次を読んだのと大差ない」状態です。

ここから「プロンプトをちゃんと作らないといけない」と気づき始めました。

---

## 改善の方向性：4つの問いを自分に立てた

試行錯誤の途中で、「自分はこのPDFから何を取り出したいのか」を整理し直しました。

そこで出てきたのが以下の4つの問いです。

- 誰向けに要約するのか（自分用？他人に渡す用？）
- どの情報を優先するのか（数字？結論？背景？）
- どの粒度で欲しいのか（3行？1ページ分？）
- どういう形式で出力してほしいのか（箇条書き？文章？）

この4つを明示してプロンプトに組み込んだら、一気に精度が上がりました。

具体的なプロンプトの変遷と、7パターンの比較は有料パートで全部公開しています。

---

## ChatGPTとの使い分けについて、正直に言うと

「ClaudeかChatGPTか」というのは宗教論争みたいになりがちなので、あくまで自分の使い方として書きます。

PDF要約に関して言うと、**Claudeの方が「読んだ感」が強い**と感じています。何というか、文脈を拾う精度が高い印象です。

たとえば、結論部分が本文の途中にさりげなく書いてあるようなPDFがあったとします。ChatGPTはそこをスルーして構成通りに要約することが多かった。Claudeはそういう場合でも「この部分が実質的な結論に見えます」と指摘してくれることがありました。

ただ、ChatGPTが優れている点もあって、「特定のフォーマットに合わせた出力」に関してはChatGPTの方がテンプレに忠実に従ってくれる印象があります。

どっちが上とかではなく、用途で使い分けるのが現実的だと思います。

## 無料でも試せる範囲について

Claudeの無料プランでもPDFの読み込み自体はできます。ただ、1日あたりの使用量に制限があるので、「大量に試す」のは難しいです。

本格的に使うならProプラン（月$20）が現実的です。僕はProで使っています。Maxプランは今のところ個人ユースでは過剰かなと感じていて、試していません。

## 試行錯誤した7パターンのプロンプト比較

ここからは、実際に使ってみたプロンプトを全パターン公開します。同じPDF（沖縄県の中小企業支援施策に関する80ページの資料）を使って、出力の質を比べています。

---

### パターン1：役割指定なし・指示最小（失敗例）

```
このPDFを要約してください。
```

**結果：**
章ごとの要点を並べた「目次の詳しい版」が返ってきた。正確性はあるが、読んで得られる情報量がほぼゼロ。

**問題点：**
「何を知りたいか」を伝えていないので、Claudeも構造を追うしかない。

---

### パターン2：役割指定あり・目的なし

```
あなたはプロのコンサルタントです。このPDFを要約してください。
```

**結果：**
パターン1よりは「意見らしいもの」が混ざるようになった。でも、どこがコンサル視点なのかよくわからない内容。役割を与えるだけでは不十分だと気づいた。

---

### パターン3：目的を明示する

```
このPDFは補助金申請の検討に使います。
申請を判断するうえで重要な条件・金額・締め切りを中心に要約してください。
他の情報は省略して構いません。
```

**結果：**
一気に実用的になった。必要な情報がピックアップされていて、そのまま意思決定に使えるレベル。所要時間は元のPDF読み込みが約90分→Claudeの要約確認で約10分。

**改善点：**
ただし、「重要だけど自分が見落としていた条件」が省かれてしまう場合がある。完全に任せるのはリスクがあると感じた。

---

### パターン4：出力形式を指定する

```
このPDFを以下の形式で要約してください。

【全体の目的】（2〜3行）
【主なターゲット】（箇条書き、3項目以内）
【重要な数字・条件】（箇条書き）
【自分が取るべきアクション】（具体的に）
```

**結果：**
形式が固定されているので、複数のPDFを比較するときに便利。出力が均一になる分、情報量は少し落ちる。

**使いどころ：**
「毎月同じジャンルのレポートを比較したい」とか「チームに展開する用のサマリーを作りたい」という場面に向いている。

---

### パターン5：思考モードを活用する（Claudeの拡張思考）

ClaudeのProプランでは、内部で長い推論を行う「思考モード（Extended Thinking）」が使えます（API経由か、claude.aiのインターフェースから設定）。

```
このPDFを読んで、表面的な構成だけでなく、
「何が本当に言いたいか」「どこが一番重要か」という観点で分析してください。
根拠となる箇所を引用しながら説明してください。
```

**結果：**
「第3章の○○という記述が実は結論に直結しているが、章立て上は中間に配置されているため見落としやすい」という指摘が来た。これは正直驚いた。自分では見逃していた箇所だった。

**注意点：**
出力が長くなりやすい。「要約」というより「分析」に近くなるので、目的に応じて使い分けが必要。

---

### パターン6：反論・弱点を聞く

```
このPDFの主張や提案に対して、批判的な視点から問題点や弱点を指摘してください。
自分が判断を間違えないために、リスクを教えてください。
```

**結果：**
「前提条件が不明確な部分がある」「比較対象のデータが古い」という指摘が来た。肯定的な要約とセットで使うと、情報の偏りが減る。

**使いどころ：**
補助金の申請判断や、事業提案の検討など、「決断のインプット」として使うPDFに向いている。

---

### パターン7：対話形式で深掘りする（これが今一番使っている方法）

1回のプロンプトで完結させるのではなく、要約してもらった後に追加で質問する方法です。

**Step1（初回）：**
```
まずこのPDFの全体像を3〜5行で教えてください。
詳細はまだ不要です。
```

**Step2（確認後）：**
```
第2章の○○について、もう少し詳しく教えてください。
自分が気にしているのは△△の部分です。
```

**Step3（必要なら）：**
```
この資料を読んで、自分が今月中に動くべきことがあれば教えてください。
```

**結果：**
一番時間はかかるけど、精度が一番高い。要約の精度より「自分が理解できているかどうか」の確認にもなるので、重要な判断をするときはこの方法を使っています。

## 実際にどれくらい時間が変わったか

同じジャンルの資料（80〜100ページ）を10本処理したときの比較です。

| 方法 | 1本あたりの処理時間 |
|---|---|
| 全部自分で読む | 約90〜120分 |
| パターン1（最小プロンプト） | 約60分（読み直しが必要） |
| パターン3〜4（目的・形式指定） | 約20〜30分 |
| パターン7（対話形式） | 約40〜50分 |

パターン3〜4を使うと、1本あたり約60〜90分の短縮になります。10本だと600〜900分、つまり10〜15時間の削減です。

「全部自分で読む必要があるかどうかを判断するためにClaudeを使う」という使い方が、実際には一番効果的でした。

## 失敗から学んだこと3つ

**1. 「全部任せる」はリスクがある**

重要な判断に使う資料は、Claudeの要約だけを信じるのは危険です。特に数字・条件・期限は必ず元のPDFで確認してください。実際に、Claudeが条件を1つスキップして要約してきたことがありました。

**2. PDFの品質が出力に影響する**

スキャンPDFや、表が多いPDFは要約の精度が落ちます。テキストとして読み込める状態のPDFの方が圧倒的に精度が高いです。画像ベースのPDFはOCR精度の問題で、Claudeが情報を読み取れないことがあります。

**3. 「要約してください」より「この目的に使います」の一言が大事**

プロンプトの中で一番効いたのは、「何のために使うか」を明示することでした。これだけで出力の質がかなり変わります。

## 応用：複数PDFの横断比較

同じジャンルのPDFが複数ある場合（たとえば、複数の補助金の要項を比べたいとき）は、以下の方法が使えます。

**Step1：それぞれのPDFを個別に要約する（パターン4の形式指定を使う）**

**Step2：要約を1つのテキストにまとめてClaudeに貼る**

**Step3：**
```
以下は3種類の補助金の要約です。
自分が申請するとしたらどれが最も適しているか、
条件・金額・難易度の観点から比較してください。
```

これで「比較表を自分で作る」作業が不要になります。3本を比較するのに以前は2〜3時間かかっていましたが、今は30〜40分で終わります。

---

## 明日から使えるアクション

1. 手元にある「読もうと思って放置しているPDF」を1本だけClaudeに読み込ませてみる
2. プロンプトに「このPDFは○○の目的で使います」の一文を加えてみる
3. 出力されたら、元のPDFの該当箇所を1〜2か所だけ確認して精度チェックする

試行錯誤の大半は「プロンプトをもっと賢くしよう」という方向に行きがちですが、一番大事なのは**「自分が何を知りたいのかを言語化する」こと**だと、この作業を通じて気づきました。

Claudeは優秀ですが、「何でも察してくれる存在」ではないです。目的を明示した分だけ、返ってくる質が変わる。それだけです。

## おわりに

プロンプトの試行錯誤って地味ですが、一度型を作ってしまえばあとは使い回せます。

今は「補助金申請用」「業界レポート理解用」「社内資料確認用」の3パターンをテンプレ化して持っています。毎回ゼロから考えなくていいので、だいぶ楽になりました。

PDFを読む時間に悩んでいる方の参考になれば嬉しいです。
