# SNS運用とClaude Codeを組み合わせた仕組みの全体像

---

## 正直に言います。半年前まで、SNS運用が続いていませんでした。

「今日も投稿できなかった」という罪悪感、わかりますか。

仕事終わりにスマホを開いて、「何を書こう…」と10分考えて、結局何も投稿せずに寝る。あの感じ。

僕もずっとそれでした。X（旧Twitter）のアカウントを作って、最初の1週間は張り切って投稿して、気づいたら2週間ほったらかし。これを何周かやりました。

変わったのは、Claude Codeを使い始めてからです。

ただ「AIに文章を書かせる」じゃなくて、**仕組みごと作った**のが効いた。今日はその全体像を説明します。

---

## 自分のSNS運用歴を振り返ると、失敗ばかりだった

僕がXを使い始めたのは2020年ごろ。最初は「副業の記録を残したい」くらいの気持ちでした。

最初の失敗：投稿内容がバラバラ。

今日はKindleの話、明日は沖縄の天気、明後日は仕事の愚痴。統一感がなくて、フォロワーが増えるわけがない。

2回目の失敗：毎日投稿チャレンジをして燃え尽きた。

「30日毎日投稿！」と宣言して、22日目で力尽きました。ネタが切れたのと、クオリティが下がってきて自己嫌悪になったのが原因です。

3回目の失敗：ChatGPTに全部書かせたら、文体がバラバラになった。

「AIに任せれば楽になる」と思って、毎日ChatGPTに「Xの投稿文を書いて」と頼んでいた時期があります。でも、出てくるのは僕の言葉じゃない文章。読んでいて「これ、俺じゃないな」という違和感があった。

3回失敗してわかったのは、**問題はツールじゃなくて仕組みだった**ということです。

---

## AIを使わないSNS運用の限界

ここで少し整理します。SNS運用を一人でやる場合、主に3つの壁があります。

**① ネタ切れ**

毎日何かを発信しようとすると、1〜2週間で「何を書けばいいかわからない」状態になります。特に「AI副業」とか「アプリ開発」みたいなテーマは、日常の中でネタを拾う訓練が必要です。

**② 文体の維持**

複数のプラットフォームに投稿するとき、Xは短く、noteは長く、Instagramはビジュアル寄りに…と、それぞれ調整が必要です。これを一人でやると、どこかのクオリティが落ちます。

**③ 継続コスト**

投稿を考えて、書いて、修正して、投稿する。このプロセスが毎日続くと、精神的な負荷が積み上がります。仕事がある日は特に。

これらを「気合いで解決する」のが従来のSNS運用でした。でも気合いには限界があります。

Claude Codeを使った仕組みは、この3つの壁を**構造で解決**します。

---

## Claude Codeで何が変わったか

最初に言っておきます。Claude Codeは「AIアシスタント」ではなく「コードを書いて実行できるAI」です。

ChatGPTに「投稿文を書いて」と頼むのとは違います。Claude Codeは、**繰り返しの作業をスクリプト化して、仕組みとして動かせる**のが強みです。

僕が最初に作ったのは、自分のブランドを定義したファイル（`CLAUDE.md`）と、投稿生成スクリプト（`generate_post.py`）の2つだけです。

試しに動かしてみたら、30分かかっていた「今日の投稿を考えて書く」作業が、5分になりました。

正確に言うと：

- 投稿案を考える：25分 → 1分（Claude Codeが候補を5つ出す）
- 文章を書く：5分 → 2分（気に入った案を選んで微調整）
- 投稿する：2分 → 2分（ここは変わらない）

数字にすると地味ですが、毎日続けると話は変わります。1週間で25分 × 7日 = 175分の節約。月換算で約12時間。

それより大きかったのは、**「今日も投稿できなかった」という罪悪感がなくなった**ことです。

## 仕組みの全体像：3つのコンポーネント

具体的に、僕が使っているSNS運用の仕組みを説明します。

構成要素は3つです。

1. **CLAUDE.md（自分のブランド定義ファイル）**
2. **ネタストック管理（Markdownのメモ）**
3. **投稿生成スクリプト（Claude Codeで動かすPythonファイル）**

それぞれを順番に説明します。

---

### ① CLAUDE.md：AIに「自分」を覚えさせる

Claude Codeのプロジェクトには、`CLAUDE.md`というファイルを置くことができます。これは「このプロジェクトのルールと文脈を書いておくファイル」です。

僕のCLAUDE.mdには以下を書いています。

```
## 筆者プロフィール
- 名前：佐伯亮
- 居住：沖縄
- 職業：会社員（副業でAI・アプリ・Kindle）
- 実績：Kindle8冊、Webアプリ2本
- 発信テーマ：AI × 副業 × 実体験

## 文章スタイル
- 一文60文字以内
- 「やってみたらこうだった」という一次情報を入れる
- 煽り表現禁止（「最強」「爆速」「革命」など）
- です・ます調、カジュアル寄り
- 具体的な数字を使う

## 禁止事項
- 「AIで月〇万円！」系の表現
- 受け売り情報だけの投稿
- 主語が曖昧な文章
```

このファイルを置いておくと、Claude Codeは毎回「このプロジェクトはこういうキャラクターで動く」という文脈を読んでから作業します。

効果は明確でした。CLAUDE.mdを置く前は、投稿文が「マーケター風の硬い文体」になりがちでした。置いた後は、僕が書いたと言っても違和感のない文章が出てくるようになりました。

---

### ② ネタストック：1日5分のメモが投稿になる

ネタ切れの本質的な原因は「ネタを貯める習慣がない」ことです。

僕が今やっているのは、**思いついたことをその場でMarkdownにメモする**だけです。`ideas/YYYY-MM-DD.md`というファイル名で、毎日1ファイル作ります。

中身はこんな感じ：

```
## 2025-06-15のメモ

- Claude Codeで投稿スクリプト作ったら、生成が早くなった
- 沖縄は梅雨明けしそう。仕事の集中力が上がる
- Kindleの印税が少し入った。副業の継続が大事だと実感
- アプリのバグ修正に2時間かかった。デバッグログの重要性
```

これを書くのに5分もかかりません。

このメモをClaude Codeに渡すと、Xの投稿案を5つ生成してくれます。使うのはそのうち1〜2個だけ。残りは翌日以降のネタストックに回します。

ポイントは「ネタを投稿できる形にしようとしない」ことです。メモはあくまでも素材。加工はAIに任せる。この分業が機能するようになってから、ネタが尽きることはなくなりました。

---

### ③ 投稿生成スクリプト：コマンド1つで候補が出る

実際に使っているスクリプトの動作を説明します（コードそのものは後述のテンプレートに含めています）。

動作の流れ：

1. 今日のメモファイルを読み込む
2. CLAUDE.mdのスタイルルールを読み込む
3. Claude APIに送信して、X投稿案を5つ生成する
4. `output/YYYY-MM-DD_posts.md`に保存する

コマンドはこれだけです：

```bash
python generate_post.py --date 2025-06-15
```

実行すると、2〜3分で候補が出てきます。

出てきた候補を見て、気に入ったものに少し手を加えて投稿する。この工程が全部で5分以内に収まります。

---

### 文体を保ちながらAIに書かせるコツ

「AIに書かせると自分らしくない文章になる」という問題は、プロンプトの工夫で解決できます。

僕が実際に使っているプロンプトの核心部分はこれです：

```
あなたは佐伯亮という沖縄在住の会社員として投稿を書きます。
以下のルールを必ず守ってください。

- 一人称は「僕」
- 体験談として書く（「〜してみた」「〜だとわかった」）
- 文末は「〜です」「〜ました」「〜でした」を混ぜる
- 「！」は1投稿に1個まで
- 改行は意味のある区切りにのみ使う

今日のメモをもとに、Xの投稿案を5つ作ってください。
各案は140字前後で、ハッシュタグは2個以内です。
```

このプロンプトを変えずに使い続けることが大事です。毎回違うプロンプトを試すと、文体がぶれます。

### 実際の投稿パフォーマンス（3ヶ月分のデータ）

数字は正直に書きます。

**Before（仕組み化前：2025年1月）**
- 月間投稿数：11本（目標30本）
- 平均インプレッション：87
- 平均いいね：2.3
- フォロワー増加：+12人

**After（仕組み化後：2025年4月）**
- 月間投稿数：28本（目標30本に近づいた）
- 平均インプレッション：312
- 平均いいね：8.7
- フォロワー増加：+67人

インプレッションは約3.6倍、いいね数は約3.8倍になりました。

ただし、これは「AIが優秀だから」ではないと思っています。単純に**投稿数が増えたことで、露出の絶対量が増えた**のが主な要因です。

バズった投稿もあります。一番伸びたのは「Claude Codeでスクリプトを作ったら、3時間かかっていた作業が20分になった」という投稿で、インプレッション2,847、いいね43でした。これも実体験ベースの投稿です。

「体験談 × 具体的な数字」が刺さるというのは、3ヶ月やってみての実感です。

### 複数プラットフォームへの展開

仕組みができると、他のプラットフォームへの展開も楽になります。

僕が今やっているのは、**X用の投稿をベースに、noteとThreadsへ展開する**パターンです。

- X（140字前後）：一次情報の核心だけ
- Threads（300〜400字）：Xの投稿に背景や補足を加える
- note（2,000字以上）：Threads投稿をさらに深掘りした記事

このnote記事もその流れで作っています。最初はXのメモ、次にThreadsで下書き、最後にnoteで体系化。

スクリプトは`--platform`オプションで切り替えられるようにしています：

```bash
python generate_post.py --date 2025-06-15 --platform threads
python generate_post.py --date 2025-06-15 --platform note_outline
```

`note_outline`を指定すると、今日のメモから1,000字程度のnoteアウトラインを生成します。全部Claude Codeに書かせるのではなく、骨格だけ作ってもらって、肉付けは自分でやっています。

### 今日から使えるSNS×AI活用テンプレート

以下に、実際に使っているファイルとプロンプトをまとめます。

**テンプレート一覧**

1. `CLAUDE.md`の基本構成（筆者情報・スタイルルール・禁止事項）

### まとめ：仕組みは1回作ったら動き続ける

SNS運用に必要なのは「やる気」ではなく「仕組み」だと、3ヶ月やってみて確信しました。

仕組みを作るのに最初かかった時間は約8時間です。CLAUDE.mdの設計が3時間、スクリプトの作成が5時間。でも、その後は毎日5〜10分で投稿が回っています。

今日から始めるなら、まずCLAUDE.mdだけ作ってください。スクリプトは後でいい。「自分がどんな発信をしたいか」を文章で定義するだけで、AIへの指示がぐっと楽になります。

この記事に書いたテンプレートを使えば、明日から投稿の質と量が変わります。ぜひ試してみてください。
